## Purpose

Manages how network traffic is routed: a SOCKS5 proxy listener, custom DNS resolution, and split tunneling (per-application VPN bypass). Provides frontend configuration that is enforced at the daemon level, plus platform-specific application discovery (Windows Start Menu shortcuts, Linux freedesktop entries) and Windows executable icon extraction.

## Requirements

### Requirement: SOCKS5 Proxy Enablement

The backend SHALL enable a SOCKS5 proxy via the `enable_socks5` command, accepting a listen address and exit configuration and forwarding it to the daemon.

#### Scenario: Enable SOCKS5 listener
- **GIVEN** the frontend invokes `enable_socks5` with a listen address and exit node
- **WHEN** the backend receives the command
- **THEN** it translates the request to daemon SOCKS5 settings and calls `vpnd.enable_socks5`

#### Scenario: Query SOCKS5 status
- **GIVEN** the SOCKS5 proxy is enabled
- **WHEN** the SOCKS5 status is queried
- **THEN** the status reflects the active connection count and state (Disabled, Idle, Connected, or Error)

### Requirement: SOCKS5 Proxy Disablement

The backend SHALL stop the SOCKS5 listener and clear its settings via the `disable_socks5` command.

#### Scenario: Disable SOCKS5
- **GIVEN** the SOCKS5 proxy is enabled
- **WHEN** `disable_socks5` is invoked
- **THEN** `vpnd.disable_socks5` is called and the status transitions to Disabled

### Requirement: Custom DNS Resolution

The system SHALL allow overriding default DNS servers with a user-supplied list of IP addresses, gated by an enable flag, both forwarded to the daemon.

#### Scenario: Set custom DNS servers
- **GIVEN** the user enters custom DNS servers in DNS settings
- **WHEN** the set-custom-DNS command runs
- **THEN** the list of IP addresses is sent to `vpnd.set_custom_dns`

#### Scenario: Enable custom DNS
- **GIVEN** custom DNS is disabled
- **WHEN** the enable-custom-DNS command runs with `true`
- **THEN** the daemon is instructed to apply the custom DNS list

### Requirement: Split Tunnel App Discovery

The system SHALL enumerate installed applications on Windows and Linux for split-tunnel selection, and SHALL merge apps imported from the daemon config with discovered and custom apps.

#### Scenario: Discover Windows apps
- **GIVEN** the Windows platform
- **WHEN** the app list is requested
- **THEN** Start Menu `.lnk` shortcuts are scanned, target executables are resolved, and entries such as uninstallers are filtered out

#### Scenario: Discover Linux apps
- **GIVEN** the Linux platform
- **WHEN** the app list is requested
- **THEN** freedesktop `.desktop` entries of type Application that are not hidden are parsed and their icons resolved

### Requirement: Custom Split Tunnel Apps

The system SHALL persist user-added executable paths in the embedded database and reject duplicates.

#### Scenario: Add a custom app
- **GIVEN** the user selects an executable via the file picker
- **WHEN** the custom app is added
- **THEN** the file is validated, an icon is extracted where applicable, and the entry is persisted

#### Scenario: Reject duplicate
- **GIVEN** a custom app path already exists in the list
- **WHEN** the same path is added again
- **THEN** a duplicate error is returned

### Requirement: Split Tunneling Activation (Windows)

The system SHALL enable per-app VPN bypass only on Windows; on other platforms split-tunnel operations are no-ops with a warning.

#### Scenario: Enable split tunneling on Windows
- **GIVEN** the Windows platform
- **WHEN** split tunneling is enabled
- **THEN** the daemon is instructed to activate split-tunnel mode

#### Scenario: No-op on non-Windows
- **GIVEN** a non-Windows platform
- **WHEN** an add-app-to-split-tunnel command is invoked
- **THEN** a warning is logged and the command returns successfully without effect

### Requirement: Split Tunnel App Management

The system SHALL add and remove individual applications from the split-tunnel list and apply changes to the daemon.

#### Scenario: Remove an app
- **GIVEN** an app is in the split-tunnel list
- **WHEN** the remove-app command is invoked
- **THEN** `vpnd.remove_split_tunnel_app` removes it from the daemon config

### Requirement: Windows App Icon Extraction

The system SHALL extract and cache application icons from Windows PE executables to local PNG files, reusing the cache on subsequent requests.

#### Scenario: Cached icon reuse
- **GIVEN** an icon for an executable was previously extracted
- **WHEN** extraction is requested again for the same executable
- **THEN** the cached PNG path is returned without re-extraction
