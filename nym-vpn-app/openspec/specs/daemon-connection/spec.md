# Daemon Connection Specification

## Purpose

Manages the gRPC connection to the `nym-vpnd` daemon process, including connection establishment, authentication retry, and error-driven reconnection. Checks daemon version compatibility, reports daemon status to the frontend, and brokers feature flags and network-environment information from the daemon.

## Requirements

### Requirement: Connection Establishment

The client SHALL lazily establish the gRPC connection to `nym-vpnd` on the first RPC call, tracking connection state as Connected, Trying, or AuthenticationDenied.

#### Scenario: First RPC opens the connection
- **GIVEN** no daemon connection has been established
- **WHEN** the first daemon RPC is invoked
- **THEN** a new RPC client is created and, on success, the connection state moves to Connected

#### Scenario: Authentication required
- **GIVEN** the daemon requires authentication
- **WHEN** the RPC client creation returns an authentication-required error
- **THEN** the connection state moves to AuthenticationDenied and an authentication error is returned to the caller

### Requirement: Version Compatibility Check

The client SHALL check the daemon's reported version against the SemVer requirement declared in `vpnd_compat.toml` and report a `NonCompat` status when the requirement is not satisfied.

#### Scenario: Incompatible daemon version
- **GIVEN** the daemon reports a version below the configured compatibility requirement
- **WHEN** the daemon status is evaluated
- **THEN** the status becomes `NonCompat { current, requirement }`

#### Scenario: Compatible daemon version
- **GIVEN** the daemon reports a version satisfying the compatibility requirement
- **WHEN** the daemon status is evaluated
- **THEN** the status becomes `Ok` carrying the daemon info

### Requirement: Daemon Status Reporting

The client SHALL expose daemon status to the frontend as one of four states: `Ok`, `NonCompat`, `Down`, or `AuthDenied`.

#### Scenario: Daemon running and compatible
- **GIVEN** the daemon is running with a compatible version
- **WHEN** the `daemon_status` command is invoked
- **THEN** it returns `Ok` with the daemon info (version, network, git commit)

#### Scenario: Daemon not running
- **GIVEN** the daemon process is not running
- **WHEN** an RPC connection attempt fails
- **THEN** the app state is set to `Down` and the frontend surfaces a "not connected to the daemon" condition

### Requirement: Feature Flag Brokering

The client SHALL query and expose daemon feature flags (including `quic`, `domain_fronting`, and `zknym_credential`) to the frontend.

#### Scenario: Feature flag reported as enabled
- **GIVEN** the daemon reports a feature flag as enabled
- **WHEN** the feature flags are queried
- **THEN** the corresponding flag is exposed as `true` to the frontend

#### Scenario: Feature gates UI affordance
- **GIVEN** the `domain_fronting` flag is `false`
- **WHEN** the anti-censorship settings render
- **THEN** the domain fronting toggle is hidden

### Requirement: Authentication Retry

The client SHALL support retrying authentication after the user grants daemon access, moving the connection state back to Trying and re-attempting the connection.

#### Scenario: Retry after access granted
- **GIVEN** the connection is in the AuthenticationDenied state
- **WHEN** the user grants permission and the retry-authentication command is invoked
- **THEN** the connection state moves to Trying and the next RPC re-attempts the connection

### Requirement: RPC Error Recovery

The client SHALL drop the RPC connection on transport or RPC errors and re-establish it on the next call.

#### Scenario: Transport error drops connection
- **GIVEN** an active daemon connection
- **WHEN** an RPC call fails with a transport error
- **THEN** the connection is dropped, the state becomes Trying, and the next command re-establishes the connection

### Requirement: Network Environment & Compatibility Tracking

The client SHALL retrieve the daemon's network environment (e.g. Mainnet/Canary/Sandbox) and network compatibility versions, caching them in app state for the frontend.

#### Scenario: Daemon info query
- **GIVEN** the daemon is reachable
- **WHEN** the daemon-info RPC is invoked
- **THEN** the version, network environment, and git commit are returned and propagated to the frontend
