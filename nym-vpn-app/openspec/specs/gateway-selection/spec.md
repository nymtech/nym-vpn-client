# Gateway Selection Specification

## Purpose

Handles gateway discovery, filtering, grouping, and selection across three gateway types (mixnet entry, mixnet exit, WireGuard). Resolves country/region metadata, ranks gateways by performance score, enforces gateway-independence constraints, and evaluates tentative gateways when network topology changes invalidate prior selections.

## Requirements

### Requirement: Gateway Type Discovery

The backend SHALL fetch gateways from the daemon via the `get_gateways` command for three types — mixnet entry, mixnet exit, and WireGuard — returning a structure grouped by country and region.

#### Scenario: Fetch mixnet entry gateways
- **GIVEN** the `get_gateways` command is invoked with the mixnet-entry type
- **WHEN** the daemon responds
- **THEN** `vpnd.list_gateways` is called and a list of gateways grouped by country is returned

#### Scenario: Hierarchical grouping
- **GIVEN** a raw gateway list from the daemon
- **WHEN** country and region grouping is applied
- **THEN** the result is a hierarchy of country → regions → gateways

### Requirement: Gateway Performance Scoring

Each gateway SHALL carry mixnet and WireGuard performance scores (Offline, Low, Medium, High), and gateways SHALL be sorted by the relevant score in descending order.

#### Scenario: Sort gateways by performance
- **GIVEN** a region containing multiple gateways
- **WHEN** the gateways are sorted by performance
- **THEN** they are ordered descending by the mixnet score (entry/exit) or WireGuard score

### Requirement: Node Selection Modes

The system SHALL support four node selection modes via the `Node` enum — Country, Region, Gateway (by identity), and Random — convertible to daemon entry/exit points.

#### Scenario: Select gateway by country
- **GIVEN** the user selects a country for the entry node
- **WHEN** the selection is converted to a daemon entry point
- **THEN** it becomes a country-based entry point with the two-letter ISO code

#### Scenario: Select a specific gateway
- **GIVEN** the user selects a specific gateway by identity
- **WHEN** the selection is converted
- **THEN** the identity is parsed and passed as a gateway-based entry point

### Requirement: Gateway Independence

The system SHALL enforce gateway-independence constraints via the `set_gateway_independence` command, controlling whether entry and exit gateways must be from different autonomous systems/networks.

#### Scenario: Enable independence
- **GIVEN** the user enables gateway independence in settings
- **WHEN** `set_gateway_independence(true)` is invoked
- **THEN** the corresponding daemon RPC enabling independence is called

#### Scenario: Relaxed criteria prompt
- **GIVEN** the topology changed and prior selections no longer satisfy independence
- **WHEN** tentative gateways are evaluated
- **THEN** a "needs relaxed independence criteria" result is returned to prompt the user

### Requirement: Gateway Independence Notifications

The system SHALL allow toggling gateway-independence reminder notifications via the `set_gateway_independence_notifications` command.

#### Scenario: Toggle independence notifications
- **GIVEN** the user changes the notification preference
- **WHEN** `set_gateway_independence_notifications(enabled)` is invoked
- **THEN** the corresponding daemon RPC is called with the new value

### Requirement: QUIC Protocol Advertisement

Each gateway SHALL advertise QUIC support via a `quic` boolean derived from its bridge transports, and region/country aggregates SHALL reflect QUIC availability.

#### Scenario: QUIC available in a region
- **GIVEN** a region containing a gateway that supports QUIC
- **WHEN** the region aggregate is built
- **THEN** the region is marked as QUIC-available

### Requirement: Country Data Resolution

The system SHALL resolve country names from ISO 3166-1 alpha-2 codes, with a special case for Kosovo (XK), ensuring all gateways carry valid country metadata.

#### Scenario: Resolve standard country
- **GIVEN** a gateway location with a standard ISO country code
- **WHEN** the country is resolved
- **THEN** the matching country name is returned

#### Scenario: Resolve Kosovo
- **GIVEN** a location with the Kosovo code (XK)
- **WHEN** the country is resolved
- **THEN** it resolves to "Kosovo" despite not being a standard ISO entry

### Requirement: Frontend Gateway Caching

The frontend SHALL cache gateway lists per type in a Zustand slice with per-type loading/error state, and SHALL serve cached data within the cache window (or stale data when the daemon is down).

#### Scenario: Cache on fetch
- **GIVEN** no cached data for a gateway type and not currently loading
- **WHEN** `fetchGateways` is called for that type
- **THEN** the loading flag is set, gateways are fetched, and the result is cached for the cache duration
