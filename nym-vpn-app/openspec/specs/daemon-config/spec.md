# Daemon Config Specification

## Purpose

Encapsulates the daemon configuration structures (mixnet traffic tuning and VPN service settings) serialized and transmitted to `nym-vpnd` over gRPC. Provides type-safe representations of mixing delays, cover-traffic rates, performance thresholds, DNS/network options, split-tunnel and geo-exclusion settings, VPN mode, and fronting mode, translated between the Rust backend and the TypeScript frontend via `ts-rs`.

## Requirements

### Requirement: Mixnet Traffic Configuration

The system SHALL store and apply mixnet traffic tuning parameters (mixing delay, Poisson-rate disable flag, background cover-traffic control, performance thresholds) via the set-mixnet-traffic-config command.

#### Scenario: Apply a mixing delay
- **GIVEN** the user adjusts the mixing delay in mixnet-tuning settings
- **WHEN** the set-mixnet-traffic-config command runs
- **THEN** the config is translated to the daemon type and sent via the corresponding RPC

#### Scenario: Disable Poisson rate
- **GIVEN** a config with the Poisson-rate disable flag set
- **WHEN** the config is applied
- **THEN** Poisson-rate-based cover traffic generation is disabled

### Requirement: Mixnet Traffic Defaults

The system SHALL expose default mixing delays and background/continuous traffic options for the tuning UI presets.

#### Scenario: Provide tuning defaults
- **GIVEN** the frontend needs to populate the mixnet tuning UI
- **WHEN** the mixnet-traffic-defaults query is invoked
- **THEN** min/max/default mixing delays and the available background and continuous traffic options are returned

### Requirement: Daemon Config Assembly

The system SHALL assemble the app-facing daemon config from the daemon's VPN service config, converting entry/exit nodes, DNS, VPN mode, split-tunnel, geo-exclusion, and gateway-selection settings.

#### Scenario: Convert daemon config
- **GIVEN** the daemon returns its VPN service config
- **WHEN** the config is converted for the app
- **THEN** entry/exit nodes, custom DNS, VPN mode, and nested settings are transformed into app-facing structures

### Requirement: Performance Thresholds

The config SHALL carry minimum acceptable node performance thresholds (mixnode and gateway VPN performance) used for node selection filtering.

#### Scenario: Gateway performance threshold
- **GIVEN** a minimum gateway VPN performance is configured
- **WHEN** gateways are filtered for selection
- **THEN** only gateways meeting or exceeding the threshold are eligible

### Requirement: DNS And Network Settings

The config SHALL store DNS configuration (custom servers + enable flag) alongside network isolation options such as allow-LAN and disable-IPv6.

#### Scenario: Apply custom DNS settings
- **GIVEN** the user enables custom DNS with a server list
- **WHEN** the config is applied to the daemon
- **THEN** the enable flag is true and the custom DNS list is set

### Requirement: Split Tunnel And Geo-Exclusion Config

The config SHALL carry per-app split-tunnel routing policies and country-level exit-node geo-exclusion settings.

#### Scenario: Geo-exclusion of countries
- **GIVEN** geo-exclusion is enabled with a list of excluded countries
- **WHEN** the daemon config is constructed
- **THEN** geo-exclusion is enabled and the excluded-countries list restricts exit-node selection

### Requirement: VPN Mode Derivation

The config SHALL derive the VPN mode (Mixnet vs WireGuard) from the two-hop flag.

#### Scenario: Derive mode from two-hop flag
- **GIVEN** the daemon config has the two-hop flag disabled
- **WHEN** the config is converted
- **THEN** the VPN mode is Mixnet

### Requirement: Fronting Mode Configuration

The config SHALL represent the anti-censorship domain-fronting strategy (Off, OnRetry, Always) applied to API requests.

#### Scenario: Force domain fronting
- **GIVEN** the user selects the Always fronting mode
- **WHEN** the set-fronting-mode command runs
- **THEN** the daemon is instructed to always route API requests through domain-fronted channels
