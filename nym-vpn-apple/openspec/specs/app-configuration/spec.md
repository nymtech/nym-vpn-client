## Purpose

Manages app settings persistence (app-group-shared `@AppStorage`/UserDefaults), network environment switching (mainnet/canary/sandbox), feature-flag fetching from the active network environment, data migrations (production mainnet enforcement), account-link refresh, and mixnet traffic-tuning configuration.

## Requirements

### Requirement: Environment Persistence

The system SHALL persist the current environment in an app-group-shared store so the tunnel extension reads the same value as the app.

#### Scenario: Shared environment value
- **GIVEN** the user switches the app environment
- **WHEN** the value is stored in the shared defaults
- **THEN** the tunnel extension and a relaunched app observe the same environment

### Requirement: Environment Switching

The system SHALL reconfigure the network environment when it changes, restricted to TestFlight/macOS, refreshing dependent state such as account links.

#### Scenario: Switch to canary on TestFlight
- **GIVEN** a TestFlight build
- **WHEN** the environment is changed to canary
- **THEN** the environment is reconfigured and account links are refreshed

### Requirement: Feature Flags Refresh

The system SHALL refresh feature flags periodically and on environment change, sourcing them from the current network environment (iOS) or the daemon (macOS).

#### Scenario: Refresh on environment change
- **GIVEN** an environment-change observer is registered
- **WHEN** the environment changes
- **THEN** feature flags are re-fetched from the current environment

#### Scenario: Periodic refresh
- **GIVEN** the app has been running past the refresh interval
- **WHEN** the refresh timer fires
- **THEN** feature flags are refreshed

### Requirement: Settings Keys Storage

The system SHALL persist user toggles via app storage keys and restore them on relaunch.

#### Scenario: Toggle persists and restores
- **GIVEN** the user changes a setting toggle
- **WHEN** the app is relaunched
- **THEN** the toggle value is restored from persistent storage

### Requirement: Mixnet Tuning Configuration

The system SHALL represent mixnet traffic tuning (background cover-traffic rate, continuous traffic rate, Poisson-rate disable) as a codable config consumed by the tunnel.

#### Scenario: Select tuning rates
- **GIVEN** the user selects background and continuous traffic rates
- **WHEN** the tuning config is built
- **THEN** it produces the corresponding mixnet traffic configuration for the tunnel

### Requirement: Account Links Refresh

The system SHALL fetch account, sign-in, and sign-up links asynchronously from the network environment (iOS) or daemon (macOS), keyed by locale and account.

#### Scenario: Refresh links after credential import
- **GIVEN** a credential is imported
- **WHEN** the account-links refresh runs
- **THEN** the links are fetched and published for the settings UI

### Requirement: Debug Logs Flag

The system SHALL select a debug log level when running on TestFlight or when the debug-logs toggle is enabled, and an info level otherwise, sharing the value with the tunnel extension.

#### Scenario: Debug level on TestFlight
- **GIVEN** a TestFlight build
- **WHEN** the debug level is evaluated
- **THEN** it resolves to debug

### Requirement: Migration To Mainnet

The system SHALL force the environment to mainnet on production builds when a non-mainnet value is found.

#### Scenario: Reset stray environment
- **GIVEN** a production build with a non-mainnet stored environment
- **WHEN** migrations run at launch
- **THEN** the environment is reset to mainnet
