# Diagnostics & Logging Specification

> Generated by openlore on 2026-06-26
> Source files: `Services/Sources/Services/SentryManager/SentryManager.swift`, `ServicesMutual/Sources/NymLogger/*`, `ServicesMutual/Sources/ErrorReason/ErrorReason.swift`, `Services/Sources/Services/NetworkMonitor/NetworkMonitor.swift`, `Settings/Sources/Settings/Logs/LogsViewModel.swift`, `Settings/Sources/Settings/DiagnosticTool/DiagnosticToolView.swift`

## Purpose

Implements file-based logging with size/age rotation, opt-in Sentry error reporting, network reachability monitoring, error-reason mapping for user-facing and system errors, an in-app log viewer with export, and a macOS diagnostic-report tool.

## Requirements

### Requirement: File Log Handler

The system SHALL bootstrap the logging system with a file log handler that writes formatted, timestamped entries, serializing writes across threads.

#### Scenario: Write a log entry
- **GIVEN** a logger emits a message
- **WHEN** the file log handler processes it
- **THEN** a formatted, timestamped line is written to the log file

#### Scenario: Concurrent writes serialize
- **GIVEN** multiple threads log simultaneously
- **WHEN** entries are written
- **THEN** writes are serialized so entries do not interleave

### Requirement: Log File Management

The system SHALL write logs to type-specific paths, delete files exceeding size or age limits, and zip log files for export.

#### Scenario: Rotate oversized log
- **GIVEN** a log file exceeds the size limit
- **WHEN** the size check runs
- **THEN** the file is deleted and subsequent logs start a new file

#### Scenario: Export logs
- **GIVEN** the user exports logs
- **WHEN** the export runs
- **THEN** the log files are zipped and a shareable URL is returned

### Requirement: Sentry Opt-In

The system SHALL enable Sentry error reporting only when the user opts in, and disable/close it when the toggle is turned off, reacting to runtime changes.

#### Scenario: Enable reporting
- **GIVEN** the user enables error reporting
- **WHEN** the toggle change is observed
- **THEN** Sentry is configured with its DSN and begins reporting

#### Scenario: Disable reporting
- **GIVEN** Sentry is active
- **WHEN** the user disables error reporting
- **THEN** the Sentry client is closed and no further reports are sent

### Requirement: Error Reason Mapping

The system SHALL map backend error-state reasons and reconstructed NSError domains into a user-facing error-reason enum.

#### Scenario: Map a backend error
- **GIVEN** the backend reports a max-devices-reached error
- **WHEN** the error is mapped
- **THEN** it becomes the corresponding error-reason case with a localized description

### Requirement: Network Reachability Monitoring

The system SHALL monitor network path changes and tunnel status, publishing availability and connection type, and suppressing false offline signals during tunnel bring-up.

#### Scenario: Offline detected
- **GIVEN** the device loses its network path
- **WHEN** the path update fires unsatisfied
- **THEN** availability is published as false

#### Scenario: Suppress during connect
- **GIVEN** the tunnel is connecting
- **WHEN** reachability is evaluated
- **THEN** availability is treated as available to avoid a false offline state

### Requirement: Log Viewing

The system SHALL provide an in-app log viewer that tails recent lines, paginates older entries, switches log file types, and supports deleting all logs.

#### Scenario: Tail recent logs
- **GIVEN** the user opens the log viewer
- **WHEN** logs are read
- **THEN** the most recent lines are shown first

#### Scenario: Delete logs
- **GIVEN** the user confirms deletion
- **WHEN** the delete runs
- **THEN** all log files are removed, caches cleared, and a reconfigure notification is posted

### Requirement: Diagnostic Tooling (macOS)

The system SHALL provide a macOS diagnostic tool that requests a diagnostic report from the daemon, pretty-prints it, and supports copy and file export.

#### Scenario: Run diagnostics
- **GIVEN** the user runs diagnostics on macOS
- **WHEN** the daemon returns a diagnostic report
- **THEN** the report is pretty-printed and displayed with copy/share options
