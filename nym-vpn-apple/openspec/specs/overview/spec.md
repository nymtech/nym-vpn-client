## Purpose

`nym-vpn-apple` is the NymVPN client for iOS, iPadOS, and macOS, built in Swift/SwiftUI and organized as a multi-module Swift Package workspace. It provides VPN connection control, account and subscription management, gateway/location selection, anti-censorship and privacy settings, diagnostics, and self-update. The app integrates the Nym mixnet core: on iOS via a bundled mixnet library inside a NetworkExtension packet tunnel; on macOS via gRPC to a privileged helper daemon.

## Requirements

### Requirement: Cross-Platform Apple Client

The system SHALL run on iOS, iPadOS, and macOS from a shared codebase, factoring platform-specific behavior into platform modules (iOS, macOS) and sharing common logic in mutual modules.

#### Scenario: Platform-specific module selection
- **GIVEN** the app runs on a given Apple platform
- **WHEN** a platform-specific capability is needed
- **THEN** the corresponding platform module provides it while shared types come from the mutual modules

### Requirement: Dual Tunnel Backend

The system SHALL connect the VPN through a NetworkExtension packet tunnel on iOS/iPadOS and through a gRPC privileged daemon on macOS, behind a unified connection-management API.

#### Scenario: iOS tunnel path
- **GIVEN** the app runs on iOS
- **WHEN** the user connects
- **THEN** the connection is established through the NetworkExtension tunnel provider

#### Scenario: macOS daemon path
- **GIVEN** the app runs on macOS
- **WHEN** the user connects
- **THEN** the connection is driven through the gRPC daemon

### Requirement: Two Tunnel Modes

The system SHALL support mixnet 5-hop and WireGuard 2-hop tunnel modes with entry/exit gateway selection.

#### Scenario: Mode selection affects routing
- **GIVEN** the user chooses a tunnel mode
- **WHEN** a connection is established
- **THEN** the routing reflects the selected mixnet 5-hop or WireGuard 2-hop mode

### Requirement: Account-Gated Connectivity

The system SHALL require a stored, active account to establish a VPN connection, surfacing account and subscription state to the user.

#### Scenario: Connect requires account
- **GIVEN** no active account is stored
- **WHEN** the user attempts to connect
- **THEN** the connection is gated on account readiness and the account state is surfaced
