## Purpose

Manages, on macOS, gRPC communication with the privileged helper daemon (`net.nymtech.vpn.helper`) via an RPC client, daemon installation/lifecycle through ServiceManagement, split-tunnel application discovery and configuration sync, full-disk-access checks, and daemon version/status tracking. This domain backs the macOS path of connection management.

## Requirements

### Requirement: RPC Client Initialization

The system SHALL initialize the RPC client and establish a streaming event listener, retrying with a delay when the daemon is unavailable.

#### Scenario: Establish event stream
- **GIVEN** the gRPC manager is set up
- **WHEN** the RPC client initializes successfully
- **THEN** an event listener is attached and the daemon event stream begins flowing

#### Scenario: Retry on failure
- **GIVEN** the RPC client fails to initialize
- **WHEN** the error is handled
- **THEN** the error is logged and setup is retried after a delay

### Requirement: Tunnel State Subscription

The system SHALL consume daemon tunnel events from a streaming observer and update published state (tunnel status, connection info, error reason, connected date) on the main actor.

#### Scenario: Apply daemon event
- **GIVEN** the daemon emits a tunnel event
- **WHEN** the observer yields it
- **THEN** the corresponding published properties are updated on the main actor

### Requirement: App Discovery Enumeration

The system SHALL enumerate installed applications for split tunneling, extracting name, executable path, and icon, excluding the app itself.

#### Scenario: Enumerate apps for split tunnel
- **GIVEN** the split-tunnel UI is opened
- **WHEN** app discovery runs
- **THEN** an alphabetically sorted list of apps with executable paths and icons is produced

### Requirement: Split Tunnel Config Sync

The system SHALL sync split-tunnel configuration to the daemon using a diff, toggling the enable flag and adding/removing only the changed app paths.

#### Scenario: Apply config diff
- **GIVEN** the split-tunnel selection changes
- **WHEN** the config sync runs
- **THEN** the enable flag is updated if changed and only added/removed app paths are sent to the daemon

### Requirement: Full Disk Access Check

The system SHALL query the daemon for full-disk-access permission and gate split-tunnel functionality on the result.

#### Scenario: Gate on missing access
- **GIVEN** the split-tunnel screen is shown
- **WHEN** the full-disk-access check returns false
- **THEN** the split-tunnel UI is disabled with a warning

### Requirement: Daemon Installation

The system SHALL direct the user to enable the privileged helper via System Settings Login Items and detect when the daemon becomes active.

#### Scenario: Open login items
- **GIVEN** the daemon is not yet enabled
- **WHEN** the user taps to open system settings
- **THEN** System Settings opens to Login Items and the app monitors for the daemon becoming active

### Requirement: Daemon Version & Status Tracking

The system SHALL retrieve the daemon version and network name, and poll initial status until the daemon is serving, signaling an update-needed state after repeated failures.

#### Scenario: Signal update needed
- **GIVEN** the RPC connection is not ready
- **WHEN** the initial status poll exhausts its retries
- **THEN** the daemon version is set to an update-needed signal

### Requirement: Error State Mapping

The system SHALL map daemon error-state reasons to user-facing error reasons for display.

#### Scenario: Map daemon error
- **GIVEN** the tunnel enters an error state with a daemon error reason
- **WHEN** the error is resolved
- **THEN** it is mapped to a user-facing error reason and published
