# Notifications & Feedback Specification

## Purpose

Manages local notifications for VPN connection events, in-app snackbar feedback with auto-dismiss and actions, haptic impact feedback (iOS), cross-process Darwin notifications, and home-screen/menu-bar/control widgets that display and toggle VPN status.

## Requirements

### Requirement: Notification Permission Management

The system SHALL request notification authorization when first needed (e.g. on connect) with the platform-appropriate options.

#### Scenario: Request on first connect
- **GIVEN** notification permission has not been requested
- **WHEN** the tunnel status changes to connected
- **THEN** the app requests notification permission and records whether it was granted

### Requirement: Disconnect Notification Rate Limiting

The system SHALL rate-limit disconnect notifications, scheduling at most one within a fixed interval.

#### Scenario: Suppress rapid repeats
- **GIVEN** a disconnect notification was scheduled recently
- **WHEN** another disconnect notification is requested within the interval
- **THEN** the second request returns early without scheduling

### Requirement: Snackbar Queue Management

The system SHALL present snackbars sequentially — immediately when none is showing, otherwise enqueued — and present the next on dismissal.

#### Scenario: Enqueue while showing
- **GIVEN** a snackbar is currently displayed
- **WHEN** another snackbar is presented
- **THEN** it is queued and only shown after the current one is dismissed

### Requirement: Snackbar Auto-Dismissal

The system SHALL auto-dismiss a snackbar after its configured duration if it is still the current item.

#### Scenario: Auto-dismiss after duration
- **GIVEN** a snackbar with a set duration is presented
- **WHEN** the duration elapses and it is still current
- **THEN** it is dismissed

### Requirement: Snackbar Action Callbacks

The system SHALL support optional primary and secondary action callbacks triggered by snackbar buttons.

#### Scenario: Trigger action
- **GIVEN** a snackbar with an action button
- **WHEN** the user taps the action
- **THEN** the action callback executes on the main actor

### Requirement: Haptic Feedback (iOS)

The system SHALL provide impact and notification haptic feedback on iOS and treat it as a no-op on macOS.

#### Scenario: Impact on iOS
- **GIVEN** the iOS platform
- **WHEN** an impact feedback method is called
- **THEN** the corresponding haptic generator fires

### Requirement: Darwin Notification IPC

The system SHALL post and observe cross-process Darwin notifications with immediate delivery and support observer cancellation.

#### Scenario: Post a Darwin notification
- **GIVEN** a Darwin notification name
- **WHEN** it is posted
- **THEN** it is broadcast immediately on the Darwin notification center

#### Scenario: Observe and cancel
- **GIVEN** a registered Darwin notification observer
- **WHEN** the observation is cancelled
- **THEN** the observer is removed

### Requirement: Widget Timeline

The system SHALL provide widget timeline entries derived from VPN status and location values read from app-group shared storage.

#### Scenario: Build timeline entry
- **GIVEN** WidgetKit requests a timeline
- **WHEN** the timeline provider reads shared status and location values
- **THEN** it returns an entry reflecting the current VPN status and locations

### Requirement: Widget Toggle Intent

The system SHALL allow toggling the VPN from widgets via app intents, starting or stopping the tunnel based on current status and reloading timelines.

#### Scenario: Toggle from widget
- **GIVEN** the VPN is connected
- **WHEN** the user activates the widget toggle
- **THEN** the tunnel is stopped and widget timelines are reloaded
