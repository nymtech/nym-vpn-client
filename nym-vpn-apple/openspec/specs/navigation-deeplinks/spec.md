# Navigation & Deep Links Specification

> Generated by openlore on 2026-06-26
> Source files: `Routes/Sources/HomeLink.swift`, `Services/Sources/Services/DeeplinkManager/DeeplinkManager.swift`, `Services/Sources/Services/ExternalLinkManager/*`, `Services/Sources/Services/PathManager/*`, `Settings/Sources/Settings/{SettingLink,SettingsFlowCoordinator}.swift`

## Purpose

Handles app-wide navigation via enumerated route types, deep-link URL scheme parsing and dispatch (`nymvpn://`), external link opening (in-app Safari or system browser), web authentication sessions for account workflows, and app-group filesystem path management.

## Requirements

### Requirement: Home Link Routing

The system SHALL define a `HomeLink` route enum (gateway details, entry/exit gateways, settings, launch, onboarding, technical opt-ins) that is hashable, identifiable, and codable for navigation destinations.

#### Scenario: Route a home link
- **GIVEN** a home link case such as settings
- **WHEN** it is used as a navigation destination
- **THEN** it is routable with a stable identity

### Requirement: Deep Link URL Scheme Handling

The system SHALL parse `nymvpn://` URLs and dispatch by host/path: a VPN toggle path connects/disconnects, account/auth response paths route to credential or subscription-payment handling.

#### Scenario: Toggle via deep link
- **GIVEN** a `nymvpn://vpn/toggle` URL
- **WHEN** the deep link is handled
- **THEN** the connection toggle is invoked

#### Scenario: Account response with deeplink id
- **GIVEN** an account-response URL carrying a deeplink id
- **WHEN** the deep link is handled
- **THEN** the credential deeplink store handler is called with the URL

### Requirement: External URL Opening

The system SHALL open external URLs via the platform mechanism and throw an invalid-URL error for unparseable strings.

#### Scenario: Open valid URL
- **GIVEN** a valid external URL string
- **WHEN** the open-external-URL call runs
- **THEN** the platform opens the URL

#### Scenario: Reject invalid URL
- **GIVEN** an unparseable URL string
- **WHEN** the open-external-URL call runs
- **THEN** an invalid-URL error is thrown

### Requirement: In-App Safari Presentation (iOS)

The system SHALL present https URLs in an in-app Safari view on iOS, falling back to the system browser for non-https schemes.

#### Scenario: Present https in-app
- **GIVEN** an https URL on iOS
- **WHEN** the in-app browser is opened
- **THEN** the in-app Safari view is presented

### Requirement: Web Authentication Session

The system SHALL present a web authentication session with the `nymvpn://` callback scheme on iOS, dispatch the callback URL to the deep-link handler, open the URL directly on macOS, and support cancellation.

#### Scenario: Complete auth callback
- **GIVEN** a web authentication session on iOS
- **WHEN** it completes with a callback URL
- **THEN** the deep-link handler is invoked and session state is cleared

### Requirement: Settings Link Navigation

The system SHALL define a `SettingLink` enum for settings screens and map each link to a destination view in the settings flow coordinator.

#### Scenario: Navigate to a settings screen
- **GIVEN** a settings link case
- **WHEN** the flow coordinator resolves its destination
- **THEN** the corresponding settings view is constructed

### Requirement: App Group Path Management

The system SHALL provide data, cache, and config folder URLs within the app-group container, creating missing directories and excluding them from backup.

#### Scenario: Provide data folder
- **GIVEN** the data folder is requested
- **WHEN** the path manager resolves it
- **THEN** the app-group data directory is created if missing and returned

### Requirement: Web Checkout Session Management

The system SHALL retain the active authentication session and cancel/clear it (and any in-app Safari state) when dismissing web checkout sessions.

#### Scenario: Dismiss active session
- **GIVEN** a web checkout session is in progress
- **WHEN** active sessions are dismissed
- **THEN** the session is cancelled and cleared

### Requirement: Widget Deep Link

The system SHALL support a widget deep link to open the app at home, while the iOS control widget toggles the VPN directly via an app intent.

#### Scenario: Open from status widget
- **GIVEN** the user taps the status widget
- **WHEN** the widget deep link is opened
- **THEN** the app opens and routes to the home/launch view
