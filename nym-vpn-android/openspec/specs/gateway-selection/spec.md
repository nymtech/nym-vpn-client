# Gateway Selection Specification

> Generated by openlore on 2026-06-26

## Purpose

Discovers, retrieves, and caches mixnet entry/exit and WireGuard gateways from the backend; lets users pick an entry or exit hop (or automatic/best selection); filters and sorts gateways by country, region, QUIC support, and tunnel-mode performance score; and persists gateway lists in DataStore.

## Requirements

### Requirement: Gateway Fetch By Category

The system MUST fetch and cache three gateway categories — mixnet entry, mixnet exit, and WireGuard — from the backend.

#### Scenario: Cache entry gateways
- **GIVEN** the backend returns entry gateways
- **WHEN** the entry gateway cache update runs
- **THEN** the gateways are fetched for the mixnet-entry type and stored via the gateway repository

#### Scenario: WireGuard gateways for two-hop
- **GIVEN** the user is selecting in two-hop mode
- **WHEN** the hop list initializes for the exit screen
- **THEN** the list is populated from the WireGuard gateways

### Requirement: Gateway Persistence

The system SHALL persist fetched gateways in DataStore as serialized lists keyed per category and recover them on read, returning an empty set on parse failure.

#### Scenario: Round-trip persistence
- **GIVEN** entry gateways are saved
- **WHEN** they are later read back
- **THEN** the same gateways are recovered

#### Scenario: Parse failure fallback
- **GIVEN** a stored gateway value fails to parse
- **WHEN** the gateway flow maps it
- **THEN** the error is logged and an empty gateway set is returned

### Requirement: QUIC Filtering

The system SHALL filter out non-QUIC gateways when QUIC is enabled, the tunnel mode is two-hop, and the entry screen is shown.

#### Scenario: Filter to QUIC-only
- **GIVEN** QUIC enabled, two-hop mode, and the entry screen
- **WHEN** the filtered data is computed
- **THEN** only QUIC-supporting gateways remain eligible

### Requirement: Geographic Grouping And Sorting

The system SHALL group eligible gateways by country (with region/city extraction), sort countries alphabetically, and sort gateways within a country by performance score relative to the current tunnel mode.

#### Scenario: Group by country with regions
- **GIVEN** gateways across countries with regions
- **WHEN** country items are created
- **THEN** gateways are grouped by country with their regions populated and sorted by score

### Requirement: Selection Persistence

The system SHALL apply the user's chosen entry/exit point to the VPN config, handling automatic versus explicit selection algorithms.

#### Scenario: Automatic best exit
- **GIVEN** the user chooses the automatic/best exit option
- **WHEN** the selection is applied
- **THEN** a random exit point and the automatic algorithm are applied

#### Scenario: Explicit exit with random entry
- **GIVEN** the user explicitly selects an exit while entry is automatic
- **WHEN** the selection is applied
- **THEN** the explicit exit point and an auto-entry/explicit-exit algorithm are applied

### Requirement: Search Filtering

The system SHALL support case-insensitive search across country name, ISO code, region, gateway identity, and gateway display name.

#### Scenario: Search by gateway name
- **GIVEN** a search query matching a gateway identity or name
- **WHEN** the filtered data is computed
- **THEN** matching gateways are included in the results

### Requirement: Reactive Updates And Error Handling

The system SHALL expose a reactive gateway flow that updates the hop UI on changes, and SHALL handle backend cache-update failures by logging and reflecting an error state.

#### Scenario: Cache update failure
- **GIVEN** a backend gateway fetch throws
- **WHEN** the cache update runs
- **THEN** the error is logged and an error state is set in the UI
