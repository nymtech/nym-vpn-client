## Purpose

Manages persistent app settings via DataStore Preferences (theme, locale, auto-start, statistics, banners, logs), mixnet traffic tuning, split-tunneling app selection, custom DNS, anti-censorship (QUIC/stealth), geo-exclusion, network environment, domain-fronting feature-flag gating, and user-agent/platform metadata. Settings screens read from a reactive settings flow and write through repositories that also push VPN config changes.

## Requirements

### Requirement: Settings Persistence

The system SHALL store and retrieve scalar settings via DataStore Preferences with type-safe keys, falling back to defaults when a value is absent.

#### Scenario: Persist theme
- **GIVEN** a theme is set
- **WHEN** it is saved to DataStore
- **THEN** reading it back returns the same theme

#### Scenario: Default when missing
- **GIVEN** a setting key has no stored value
- **WHEN** it is read
- **THEN** the documented default value is used

### Requirement: Reactive Settings Flow

The system SHALL expose a settings flow mapping DataStore preferences to an immutable settings object, recovering defaults on mapping errors.

#### Scenario: Emit on change
- **GIVEN** the DataStore preferences change
- **WHEN** the settings flow maps them
- **THEN** a new settings object reflecting the change is emitted

### Requirement: Mixnet Traffic Tuning

The system SHALL persist and retrieve mixnet traffic configuration (cover-traffic Poisson parameter, average packet delay, message-sending delay, Poisson-rate disable), merging stored values with defaults, and SHALL compute derived latency/speed for the tuning UI.

#### Scenario: Save tuning config
- **GIVEN** a mixnet traffic configuration
- **WHEN** it is saved
- **THEN** its fields are persisted as individual values

#### Scenario: Disable background cover traffic
- **GIVEN** background cover traffic is disabled in the UI
- **WHEN** the configuration recalculates
- **THEN** the Poisson-rate disable is set and the message-sending delay uses its default

### Requirement: Appearance And Localization

The system SHALL support theme selection and app locale override persisted in DataStore.

#### Scenario: Persist locale
- **GIVEN** a locale is set
- **WHEN** it is saved
- **THEN** reading it back returns the same locale for language/region initialization

### Requirement: Anti-Censorship Settings

The system SHALL manage QUIC bridges and stealth mode via separate toggles, applying changes to the VPN config (and persisting the QUIC flag in settings).

#### Scenario: Enable QUIC
- **GIVEN** the user enables QUIC
- **WHEN** the toggle is applied
- **THEN** the QUIC flag is persisted and bridges are enabled in the VPN config

### Requirement: Split Tunneling App Selection

The system SHALL serialize the selected split-tunnel apps to storage and deserialize them on load, returning an empty list on parse failure.

#### Scenario: Save app selection
- **GIVEN** the user modifies the split-tunnel app set
- **WHEN** the changes are saved
- **THEN** the app list is serialized and stored

### Requirement: Custom DNS Configuration

The system SHALL enable/disable custom DNS and persist a DNS server list via the VPN config, triggering a reconnect when the tunnel is connected.

#### Scenario: Save DNS while connected
- **GIVEN** the tunnel is up
- **WHEN** a custom DNS list is saved
- **THEN** the config is updated and a reconnect is initiated

### Requirement: Geo-Exclusion Configuration

The system SHALL enable/disable geo-exclusion and allow a port override in the VPN config, surfacing a failure state on error.

#### Scenario: Enable geo-exclusion
- **GIVEN** the user enables geo-exclusion
- **WHEN** the config update succeeds
- **THEN** the failure flag is cleared

### Requirement: Domain-Fronting Feature Flag

The system SHALL query backend feature flags to determine whether domain fronting is enabled, defaulting to disabled on error.

#### Scenario: Feature flag fetch fails
- **GIVEN** the feature-flag fetch throws
- **WHEN** domain-fronting availability is queried
- **THEN** it returns false and the error is logged

### Requirement: User Agent And Platform Metadata

The system SHALL provide a user agent describing app name, version, platform (Android or Android TV), SDK level, CPU architecture, and build flavor.

#### Scenario: Android TV platform
- **GIVEN** the device is Android TV
- **WHEN** the user agent is built
- **THEN** the platform field reflects Android TV
