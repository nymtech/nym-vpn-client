## Purpose

`nym-vpn-android` is the NymVPN client for Android (phones, tablets, and Android TV), written in Kotlin with Jetpack Compose and Hilt dependency injection. It connects through the Nym mixnet via a Rust core (uniffi bindings) wrapped in an Android `VpnService`, supporting mixnet five-hop and WireGuard two-hop modes. It provides connection control, account/subscription management, gateway selection, anti-censorship and privacy settings, diagnostics, and OS integration (quick tile, shortcuts, auto-start).

## Requirements

### Requirement: Multi-Module Android App

The system SHALL be organized as a multi-module Gradle project — an `app` module plus supporting `core`, `connectivity`, `billing`, and `logcatter` modules — with the app depending on the supporting modules.

#### Scenario: Module responsibility separation
- **GIVEN** a capability such as the VPN engine, connectivity, billing, or logging
- **WHEN** it is implemented
- **THEN** it lives in its dedicated module and is consumed by the app module

### Requirement: Rust Core VPN Engine

The system SHALL perform VPN work through the Nym Rust core via uniffi bindings, wrapped in an Android VPN service, supporting mixnet five-hop and WireGuard two-hop modes.

#### Scenario: Connect through the core
- **GIVEN** the user initiates a connection
- **WHEN** the tunnel starts
- **THEN** the Android VPN service drives the Rust core to establish the selected tunnel mode

### Requirement: Account-Gated Connectivity

The system SHALL require a stored account (mnemonic) to connect, with subscription state available via Google Play billing on supported builds.

#### Scenario: Require account to connect
- **GIVEN** no account mnemonic is stored
- **WHEN** the user attempts to connect
- **THEN** the connection is gated and the user is directed to the account/auth flow

### Requirement: Distribution Flavors

The system SHALL support multiple build flavors, including a Google Play (general) flavor with in-app billing and an F-Droid flavor without it.

#### Scenario: F-Droid flavor without billing
- **GIVEN** the F-Droid flavor build
- **WHEN** billing availability is checked
- **THEN** billing is reported unavailable and billing-dependent UI is hidden
