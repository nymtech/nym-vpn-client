## Purpose

The Jetpack Compose presentation layer and app shell: the Application class and `MainActivity`, app-level navigation, theming (dark/light/system/dynamic), localization, startup splash gating, and runtime permission flows (VPN consent and notifications). It composes a unified app UI state and delegates screen-specific logic to feature view models.

## Requirements

### Requirement: Application Initialization

The Application class MUST initialize the Nym core library, configure logging, initialize the backend manager, apply the stored locale, and conditionally initialize crash reporting on creation.

#### Scenario: Initialize on create
- **GIVEN** the app launches
- **WHEN** the Application `onCreate` completes
- **THEN** the core library context is initialized, logging is configured, the backend manager is initialized, the stored locale is applied, and crash reporting is initialized if enabled

### Requirement: App Shell Navigation

The main activity MUST host a navigation graph starting at the splash route, render a contextual top navigation bar across routes, and support authentication deep links.

#### Scenario: Start at splash
- **GIVEN** the main activity is created
- **WHEN** content is rendered
- **THEN** the navigation host starts at the splash route with a contextual navigation bar

#### Scenario: Handle auth deep link
- **GIVEN** an authentication deep link arrives
- **WHEN** it is handled
- **THEN** the user is routed to the appropriate account/auth destination

### Requirement: Theme Management

The theme composable MUST apply the selected theme (automatic, dark, light, dynamic) and adjust Material color schemes, edge-to-edge insets, and system bar appearance.

#### Scenario: Apply dark theme
- **GIVEN** the user selects dark mode
- **WHEN** the theme recomposes
- **THEN** the dark color scheme and light system-bar icons are applied

#### Scenario: Dynamic color on supported devices
- **GIVEN** a device supporting dynamic color and the dynamic theme
- **WHEN** the theme recomposes
- **THEN** Material dynamic colors are applied, otherwise static schemes are used

### Requirement: Splash Gating

The splash screen MUST remain until the app is ready and the backend manager is initialized, then navigate to the main screen without returning to splash.

#### Scenario: Navigate when ready
- **GIVEN** the app is starting
- **WHEN** readiness and backend initialization both become true
- **THEN** navigation proceeds to the main screen and splash is removed from the back stack

### Requirement: Localization Management

The app view model MUST apply locale changes, persist them, and trigger an activity restart to apply the configuration change.

#### Scenario: Change locale
- **GIVEN** the user selects a new locale
- **WHEN** the locale change is applied
- **THEN** the locale is persisted and the activity restarts to apply it

### Requirement: Unified App State

The app view model MUST combine settings, VPN config, backend state, and gateway flows into a single app UI state, and expose system-message and configuration-change signals.

#### Scenario: Recombine on upstream change
- **GIVEN** any upstream flow updates
- **WHEN** the combine runs
- **THEN** a new app UI state reflecting all dependencies is emitted

### Requirement: VPN Permission Flow

The main screen MUST request VPN consent before connecting and route to a permission screen when consent is denied, offering a retry.

#### Scenario: Request consent on connect
- **GIVEN** the user taps connect
- **WHEN** VPN preparation indicates consent is needed
- **THEN** the system VPN consent dialog is launched before connecting

#### Scenario: Retry after denial
- **GIVEN** the permission screen is shown for VPN consent
- **WHEN** the user retries and consent is now granted
- **THEN** the app proceeds to the main screen with auto-start

### Requirement: Notification Permission Handling

The main screen MUST request the notifications runtime permission on supported Android versions and handle denial with a warning.

#### Scenario: Request notifications permission
- **GIVEN** a device requiring the notifications runtime permission that has not granted it
- **WHEN** the connection or stats flow triggers
- **THEN** the notifications permission is requested

### Requirement: Startup Lifecycle Orchestration

The app view model MUST run startup work (auto-start check, theme readiness, gateway cache warming, system messages, account refresh) and signal readiness when complete.

#### Scenario: Auto-start on launch
- **GIVEN** auto-start is enabled and a mnemonic is stored
- **WHEN** the startup auto-start check runs and the tunnel is down
- **THEN** the backend starts the tunnel

### Requirement: Process Lifecycle Tracking

The app MUST track foreground/background state via the process lifecycle and expose it for features to react.

#### Scenario: Return to foreground
- **GIVEN** the app was backgrounded
- **WHEN** it returns to the foreground
- **THEN** the foreground state becomes true and account state is refreshed
