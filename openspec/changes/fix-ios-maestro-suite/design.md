## Context

`nym-vpn-apple` ships a Maestro UI suite mirroring the Android setup: a `NymVPN-Mock` scheme built with `MOCK_MODE`, a mock backend (`MockConnectionState` / `MockMode`) wired into `ConnectionManager`, and flows under `nym-vpn-apple/maestro`. The infra was added once and only lightly touched since. Meanwhile the iOS UI was redesigned (`Home/Sources/26`, `onboarding26.*` / `oneClick.*` localization keys) and Android's suite was rewritten to match — iOS was not.

Two independent breakages exist:

1. **Build.** `Routes/Package.swift` declares `swift-tools-version: 6.2`, which requires Swift 6.2 / Xcode 26. On any Swift 6.1 toolchain — the local machine (Xcode 16.4) and the CI runner, whose workflow `xcode-select`s the unpinned default `/Applications/Xcode.app` — `xcodebuild build-for-testing -scheme NymVPN-Mock` fails at *Resolve Package Graph* before compiling. `Routes` is a single `Codable` enum (`HomeLink.swift`) with zero 6.2 features; its ten sibling packages use 5.9/5.10; the app deployment target is iOS 16/17 with no `#available(iOS 26)` gates.
2. **Flows.** The 7 flows assert removed copy (`"Welcome to NymVPN"`, `"Disconnected"`, `"Get started"`) and use brittle `point: "95%,12%"` taps and `visible: ".*"`. They drive an app that no longer exists.

**Correction discovered during implementation:** lowering `Routes` was necessary but not sufficient. Resolution then fails on a missing local package `NymVPNLib` — the Rust FFI core (gitignored, generated by `scripts/BuildCore.sh` → `nym-vpn-core/iOS.mk`). **51 Swift files import `NymVPNLib`**, so even the mock app must link the real core to compile. Worse: this dev machine is **Intel x86_64**, `iOS.mk` builds **device-only** `aarch64-apple-ios`, and no iOS rust targets are installed — so building the core and running Maestro **locally is not feasible here**. And `ci-maestro-ios.yml` never built the core at all, so the iOS maestro CI had never been able to build. Net effect: the build fix is a CI/infra change (build the core on Apple Silicon), and **the flow suite is authored against source-resolved copy but verified in CI, not locally.**

## Goals / Non-Goals

**Goals:**
- Make the `NymVPN-Mock` build resolve and compile on the current CI/local toolchain.
- Confirm the mock backend still compiles against current interfaces; fix drift if present.
- Rewrite all existing flows text-based against the redesigned UI, mirroring Android's style.
- Restructure into `subflows/` + per-screen folders and expand coverage to Android parity.
- Keep the suite green in `ci-maestro-ios`.

**Non-Goals:**
- No product/runtime behavior change (beyond the one-line tools version and any mock-alignment fix).
- No adoption of `accessibilityIdentifier`-based selectors — text-based is chosen to match Android. (Noted as a future option.)
- No changes to Android or macOS suites, or to the real daemon path.
- Not upgrading the project to the iOS 26 SDK / Xcode 26.

## Decisions

**D1 — Lower `Routes` to `swift-tools-version: 5.10` rather than pinning Xcode 26.**
Rationale: nothing in the codebase actually needs Swift 6.2 — `Routes` is a trivial enum, siblings are 5.9/5.10, deployment is iOS 16/17, no iOS 26 SDK usage. Lowering is one line and unblocks *both* local dev and CI regardless of runner Xcode. Alternative (pin Xcode 26 in CI via `maxim-lobanov/setup-xcode`) was rejected as the primary fix: it forces every developer onto Xcode 26 for no real benefit and leaves the gratuitous version in place. Pinning Xcode remains available as optional CI hardening (D5).

**D2 — Text-based selectors, mirroring Android.**
The redesign exposes zero `accessibilityIdentifier`s; Android selects on visible copy (`"NOT PROTECTED"`, `"Connect"`, `"Fast"`). Matching that keeps the two platforms consistent and touches no app code. Resolved English copy to assert on: onboarding `"Welcome to Nym VPN!"` + `"Get started"` (+ `"Close"` xmark), connect button `"Connect"`/`"Connecting"`/`"Disconnect"`, `"Entry server"`/`"Exit server"`, welcome `"Welcome!"`/`"Continue"`. Trade-off: brittle to copy/localization edits — accepted for parity; a11y identifiers deferred.

**D3 — Fix the build first, then discover mock drift.**
Because resolution fails before compilation, we cannot yet know whether the iOS mock has the same interface drift Android fixed. Sequence: lower `Routes` → build → read compiler output → align mock only if it fails. This avoids speculative mock edits.

**D4 — Structure mirrors Android.**
Introduce `maestro/subflows/` (`open_app`, `connect`, and a logout/reset as needed) and per-screen folders (`main_screen/`, `nodes/`, `settings_screen/`, `login/`). Map each Android flow to its iOS screen: OneClickView (main), GatewaysView/SearchView/ServerDetailsView (nodes), SettingsView + AppearanceView/DnsView/CensorshipView/SplitTunnelView/PassphraseView (settings/login).

**D5 — (Optional) Pin Xcode in `ci-maestro-ios.yml`.**
Belt-and-suspenders against the unpinned `/Applications/Xcode.app` drifting. Low priority once D1 lands, since D1 removes the 6.2 requirement entirely.

**D6 — Build the Rust core in the maestro CI (added during implementation).**
The mock links `NymVPNLib`; nothing can build without it. Rather than the invasive alternative (decouple the mock from `NymVPNLib` — rejected: 51 files import it), the maestro CI is rewritten to build the core the way the working `build-nym-vpn-apple.yml` does: `runs-on: AppleSilicon`, install rust with `aarch64-apple-ios` + `aarch64-apple-ios-sim`, cargo-swift, protoc, go, then `make -f iOS.mk` and stage `NymVPNLib` before `xcodebuild`. Because Maestro runs on the **simulator**, `iOS.mk` is changed to also emit the `aarch64-apple-ios-sim` xcframework slice (device slice, and thus the release archive, is unaffected — the change is additive). This is authored correct-by-construction and needs a real CI run to confirm (simulator libwg/xcframework linkage can't be verified from this Intel Mac).

## Risks / Trade-offs

- **Lowering `Routes` breaks its source** → Mitigation: `HomeLink.swift` uses no 6.2 features; a build after the change confirms. Low risk.
- **Hidden mock drift (Android-style)** surfaces only after the build unblocks → Mitigation: D3 sequences the build before flow work; budget a mock-alignment step.
- **Text selectors flake on copy changes** → Mitigation: assert on stable, high-signal strings; keep shared copy in subflows so a change touches one place; revisit a11y identifiers later.
- **iOS redesign lacks an Android-covered screen** → Mitigation: parity is scoped to journeys whose iOS screen exists; log any Android journey with no iOS equivalent instead of forcing a flow.
- **Simulator/onboarding-gating differences** (e.g. `onboardingDidDisplay` under `clearState`) cause the first-launch path to differ → Mitigation: capture launch + onboarding dismissal in `subflows/open_app` and verify on the real simulator.

## Migration Plan

1. Lower `Routes/Package.swift` to `5.10`; resolve + build `NymVPN-Mock`.
2. If compilation fails, align the mock backend against current interfaces.
3. Add `subflows/`; rewrite the 7 flows text-based; verify each on the `iPhone 16` simulator.
4. Add parity flows screen-by-screen, verifying as they land.
5. (Optional) Pin Xcode in `ci-maestro-ios.yml`.

Rollback: revert the `Routes` one-liner and the `maestro/` changes; no product surface is affected.
