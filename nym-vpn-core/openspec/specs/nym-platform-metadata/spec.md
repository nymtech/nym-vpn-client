# nym-platform-metadata Specification

> Generated by openlore on 2026-06-26
> Source files: src/lib.rs, src/command.rs, src/user_agent.rs, src/apple.rs, src/linux.rs, src/android.rs

## Purpose

nym-platform-metadata detects operating system and platform information at runtime
and assembles it into a `SysInfo` value. It is used to build user-agent strings for
API requests and to provide a stable, privacy-preserving identifier derived from
the host's system information.

## Requirements

### Requirement: CollectSystemInfo

The crate SHALL collect platform/OS metadata into a `SysInfo` structure using the
platform-appropriate detection method.

#### Scenario: Detect platform metadata
- **GIVEN** the engine runs on a supported OS (Apple, Linux, or Android)
- **WHEN** `SysInfo::new()` is called
- **THEN** it returns system metadata gathered via the platform-specific module

### Requirement: DeriveStableIdentifier

The crate SHALL derive a hashed identifier from the collected system information.

#### Scenario: Produce a hashed identifier
- **GIVEN** a populated `SysInfo`
- **WHEN** `hash_identifier()` is called
- **THEN** it returns a hash of the identifying fields rather than the raw values

### Requirement: BuildUserAgent

The crate SHALL produce a user-agent representation from the platform metadata for
use in outgoing HTTP requests.

#### Scenario: Format a user agent
- **GIVEN** a `SysInfo` value
- **WHEN** it is rendered for a request (via `Display`/user_agent helpers)
- **THEN** a user-agent string describing the platform and version is produced

## Technical Notes

- **Implementation**: `src/lib.rs` (`SysInfo`, `hash_identifier`), `src/user_agent.rs`, `src/apple.rs`, `src/linux.rs`, `src/android.rs`, `src/command.rs`
- **Dependencies**: platform detection crates; consumed by API clients (`nym-vpn-api-client`, `nym-statistics-api-client`) and the daemon/library for request identification
