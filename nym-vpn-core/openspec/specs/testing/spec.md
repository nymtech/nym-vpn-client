## Purpose

The testing subsystem (crates under `crates/test/`) provides end-to-end integration
testing of the Nym VPN client inside virtual machines. `test-manager` orchestrates
VMs and drives test functions from the host; `test-runner` executes inside the
target VM and performs the actual app/daemon/network operations; `test-rpc` defines
the tarpc RPC contract and transport that connect the two.

## Requirements

### Requirement: VmOrchestration

The `test-manager` SHALL provision and manage virtual machines (e.g. QEMU on Linux,
Tart on macOS) configured via a config file and VM manifest.

#### Scenario: Boot a configured VM
- **GIVEN** a `VmConfig` selected from the manager configuration
- **WHEN** the manager starts a test session
- **THEN** it provisions/boots the corresponding VM and establishes an SSH connection to it

### Requirement: TestSelectionAndExecution

The `test-manager` SHALL select tests by location/pattern and run each test function
against the target.

#### Scenario: Run a filtered test set
- **GIVEN** a `TestLocationList` glob filter
- **WHEN** `run(...)` is invoked
- **THEN** the matching test functions are executed via `run_test_function` and their results reported

### Requirement: ManagerRunnerRpcContract

The `test-rpc` crate SHALL define the RPC service contract (a `tarpc` `Service`
trait) and multiplexed transport used between the manager and the runner.

#### Scenario: Invoke a runner operation
- **GIVEN** an established `ConnectionHandle` between manager and runner
- **WHEN** the manager calls a method on the `Service` client
- **THEN** the call is serialized over the multiplexed transport and executed by the runner

### Requirement: InVmAppLifecycleControl

The `test-runner` SHALL install, uninstall, start, stop, and restart the Nym VPN
app/daemon on the target VM.

#### Scenario: Restart the daemon under test
- **GIVEN** the app is installed on the target
- **WHEN** the manager invokes the runner's restart operation
- **THEN** the runner restarts the daemon system service and reports success or a `test_rpc::Error`

### Requirement: InVmEnvironmentControl

The `test-runner` SHALL configure the daemon's environment and log level, and
enable/disable system-service startup on the target.

#### Scenario: Set daemon environment
- **GIVEN** a desired environment map and log level
- **WHEN** the manager calls `set_daemon_environment` / `set_daemon_log_level`
- **THEN** the runner applies them to the daemon on the target VM

### Requirement: NetworkProbing

The testing subsystem SHALL perform network probes (TCP/UDP/ping, HTTP/GeoIP
lookups) to verify tunnel behavior.

#### Scenario: Verify tunnel connectivity
- **GIVEN** a connected tunnel state on the target
- **WHEN** the runner issues `send_ping`/`send_tcp`/`send_udp` or a GeoIP lookup
- **THEN** the results are returned to the manager to assert expected routing/anonymization

### Requirement: TunnelAndAccountStateAssertions

The `test-manager` SHALL wait for and assert tunnel and account states during tests.

#### Scenario: Await connected state
- **GIVEN** a test that initiates a connection
- **WHEN** `wait_for_tunnel_state(...)` is called
- **THEN** the test proceeds only once the expected tunnel state is observed (or times out)

## Technical Notes

- **Implementation**: `test-manager/src/run_tests.rs` (`run`, `run_test_function`), `test-manager/src/vm/*` (QEMU/Tart/SSH/provision), `test-manager/src/tests/*` (test functions, `wait_for_tunnel_state`, `wait_for_account_state`), `test-rpc/src/lib.rs` (`#[tarpc::service] Service`), `test-rpc/src/transport.rs` (`MultiplexCodec`, `ConnectionHandle`), `test-runner/src/app_nymvpn.rs` + `package_nym.rs` (app lifecycle), `test-runner/src/net.rs` (probes)
- **Dependencies**: tarpc, tokio, ssh, QEMU/Tart, the Nym VPN proto/client; drives `nym-vpnd` and the packaged app under test (separate from shipping crates)
