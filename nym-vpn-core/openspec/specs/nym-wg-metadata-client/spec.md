# nym-wg-metadata-client Specification

> Generated by openlore on 2026-06-26
> Source files: src/lib.rs, src/error.rs

## Purpose

nym-wg-metadata-client queries WireGuard gateway metadata and manages in-tunnel
bandwidth for a WireGuard connection. It provides a client that, once the tunnel
is up, can resolve the tunnel interface name, query available bandwidth, top up
bandwidth, and check whether the gateway supports an upgrade mode.

## Requirements

### Requirement: QueryAvailableBandwidth

The client SHALL query the WireGuard gateway for the remaining available bandwidth.

#### Scenario: Check remaining bandwidth
- **GIVEN** an established WireGuard tunnel to a gateway
- **WHEN** `query_bandwidth()` is called
- **THEN** the client returns the gateway's reported `AvailableBandwidth`

### Requirement: TopUpBandwidth

The client SHALL top up bandwidth on the gateway using a credential/ticket.

#### Scenario: Replenish bandwidth
- **GIVEN** the available bandwidth is low
- **WHEN** `topup_bandwidth(...)` is called with the required credential
- **THEN** the gateway's bandwidth allowance for the connection is increased

### Requirement: DeferredClientInitialization

The client SHALL support deferred initialization that waits for the tunnel to come
up before issuing metadata queries.

#### Scenario: Wait for tunnel readiness
- **GIVEN** a `LazyMetadataClient` created before the tunnel is up
- **WHEN** the tunnel-up signal is received over the `TunUpReceiver`
- **THEN** a fully usable `MetadataClient` bound to the tunnel interface becomes available

## Technical Notes

- **Implementation**: `src/lib.rs` (`MetadataClient`, `LazyMetadataClient`, `query_bandwidth`, `topup_bandwidth`, `check_upgrade_mode`, `TunUpSender`/`TunUpReceiver`), `src/error.rs`
- **Dependencies**: tokio, nym identity/bandwidth types; consumed by `nym-vpn-lib` on the WireGuard data path
