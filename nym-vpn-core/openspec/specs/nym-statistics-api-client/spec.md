# nym-statistics-api-client Specification

> Generated by openlore on 2026-06-26
> Source files: src/lib.rs, src/client.rs, src/routes.rs, src/error.rs

## Purpose

A thin HTTP client for reporting anonymous VPN usage statistics to a Nym backend. It wraps `nym-http-api-client` to POST two report types — per-session usage reports and active-device pings — to fixed `v1/stats/*` routes, with a long request timeout suited to traffic that may traverse the mixnet, and (on iOS) the ability to bind its sockets to a specific tunnel interface.

## Requirements

### Requirement: StatisticsReportPosting

The system SHALL provide methods to POST a session report (`VpnClientStatsReportV2`) to `v1/stats/session` and an active-device report (`ActiveDeviceReport`) to `v1/stats/active_device`, serializing the body as JSON and tolerating an empty response body on success.

#### Scenario: Session report posted
- **WHEN** `post_session_report` is called with a `VpnClientStatsReportV2`
- **THEN** the report is JSON-serialized and POSTed to `v1/stats/session`, returning `Ok(())` on success or a `ReportSending` error on HTTP failure

#### Scenario: Active-device report posted
- **WHEN** `post_active_device` is called with an `ActiveDeviceReport`
- **THEN** the report is JSON-serialized and POSTed to `v1/stats/active_device`

### Requirement: ClientConstructionWithUserAgentAndTimeout

The system SHALL construct an HTTP client from a base URL and user agent, applying a fixed 30-second request timeout (because requests may traverse the mixnet) and SHALL surface a `VpnApiClientCreation` error if the underlying client cannot be built.

#### Scenario: Client built with timeout
- **WHEN** `StatisticsApiClient::new` is called with a base URL and user agent
- **THEN** an HTTP client is created with the user agent set and a 30-second timeout, or a `VpnApiClientCreation` error is returned on failure

### Requirement: IosInterfaceBinding

On iOS the system SHALL be able to produce a copy of the client whose sockets are bound to a given tunnel interface (or unbound when `None`), disabling the built-in DoH/DoT resolver so name resolution uses the system resolver and traffic does not leak outside the tunnel.

#### Scenario: Bind client to tunnel interface on iOS
- **GIVEN** the platform is iOS
- **WHEN** `with_bound_interface` is called with an interface name
- **THEN** a new client is returned whose reqwest builder is bound to that interface with the Hickory DNS resolver disabled

## Technical Notes

- **Implementation**: `src/client.rs` (client, POST helper, iOS interface binding), `src/routes.rs` (route constants), `src/error.rs`.
- **Dependencies**: `nym-http-api-client` (`Client`, `ApiClient`, `parse_response`, `UserAgent`, `HttpClientError`), `nym-statistics-common` (report DTOs), `serde`, `url`, `thiserror`. In the workspace it is the transport used by `nym-statistics`' report-sending handler to deliver collected telemetry to the backend.
