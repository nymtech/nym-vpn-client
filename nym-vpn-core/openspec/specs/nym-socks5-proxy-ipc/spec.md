# nym-socks5-proxy-ipc Specification

> Generated by openlore on 2026-06-26
> Source files: src/lib.rs

## Purpose

nym-socks5-proxy-ipc defines the IPC protocol message types exchanged between the
`nym-vpnd` daemon and the `nym-socks5-proxy` subprocess. It is a pure
types/contract crate: it specifies the messages the daemon sends to the proxy, the
status/error messages the proxy sends back, and the proxy configuration payload
(with validation).

## Requirements

### Requirement: DaemonToProxyMessages

The crate SHALL define the message variants the daemon sends to the proxy
subprocess, with stable string serialization.

#### Scenario: Encode a daemon command
- **GIVEN** the daemon needs to instruct the proxy
- **WHEN** it serializes a `DaemonMessage`
- **THEN** the message round-trips via its `Display`/`FromStr` string encoding

### Requirement: ProxyToDaemonMessages

The crate SHALL define the status and error messages the proxy sends back to the
daemon.

#### Scenario: Report proxy status
- **GIVEN** the proxy has a status or error to report
- **WHEN** it emits a `ProxyMessage` (carrying `StatusData` or `ErrorData`)
- **THEN** the daemon can parse it from its string form

### Requirement: ProxyConfigValidation

The crate SHALL define the proxy configuration payload and validate it before use.

#### Scenario: Reject invalid config
- **GIVEN** a `ProxyConfig` value
- **WHEN** `validate()` is called with invalid fields
- **THEN** it returns an error describing why the configuration is invalid

## Technical Notes

- **Implementation**: `src/lib.rs` (`DaemonMessage`, `ProxyMessage`, `ProxyConfig::validate`, `InterfaceAddresses`, `StatusData`, `ErrorData`)
- **Dependencies**: serde; shared contract between `nym-vpnd` and `nym-socks5-proxy`
