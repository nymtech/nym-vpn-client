# nym-dbus Specification

## Purpose

`nym-dbus` is a Linux-only crate that wraps the system D-Bus to integrate the VPN client with the three host services that govern networking and DNS: `org.freedesktop.systemd1` (host run state), `org.freedesktop.resolve1` (systemd-resolved DNS), and `org.freedesktop.NetworkManager` (NetworkManager DNS/WireGuard management). It exposes typed proxies to query host liveness, set/revert per-interface DNS, create/remove NetworkManager WireGuard tunnels, and watch DNS configuration changes.

## Requirements

### Requirement: SharedSystemDBusConnection

The system SHALL reuse a single lazily-created system D-Bus `SyncConnection`, wrapped in an `Arc`, across all D-Bus interactions in the crate.

#### Scenario: First connection creation
- **GIVEN** no system D-Bus connection has been established yet
- **WHEN** `get_connection()` is called
- **THEN** a new `SyncConnection::new_system()` is created, cached in a static `Mutex<Option<Arc<SyncConnection>>>`, and returned

#### Scenario: Subsequent connection reuse
- **GIVEN** a cached connection already exists
- **WHEN** `get_connection()` is called again
- **THEN** the existing `Arc<SyncConnection>` is cloned and returned without creating a new connection

### Requirement: SystemdHostRunState

The system SHALL query the `org.freedesktop.systemd1.Manager.SystemState` property to determine whether the host is in a usable run state.

#### Scenario: Reading the host run state
- **GIVEN** a system D-Bus connection to `org.freedesktop.systemd1`
- **WHEN** `is_host_running()` reads the `SystemState` property
- **THEN** it returns the property value compared against the known states (`starting`, `initializing`, `running`, `degraded`), surfacing a `ReadSystemStateError` if the property cannot be read

### Requirement: SystemdResolvedManagesResolvConf

The system SHALL verify that systemd-resolved exists and that `/etc/resolv.conf` is governed by systemd-resolved (via a stub symlink, the static stub pointing to localhost, or matching stub contents) before managing DNS through it.

#### Scenario: Initialization rejects unmanaged resolv.conf
- **GIVEN** systemd-resolved is reachable on D-Bus
- **WHEN** `SystemdResolved::new()` runs and `/etc/resolv.conf` is neither symlinked to a known resolved stub, nor a localhost-pointing static stub, nor content-matching a stub
- **THEN** construction fails with `NotSymlinkedToResolvConf` (or `StaticStubNotPointingToLocalhost`)

#### Scenario: Replacing DNS servers on a link
- **GIVEN** a valid `SystemdResolved` handle and an interface index
- **WHEN** `set_dns()` resolves the link via `GetLink` and calls `SetDNS`
- **THEN** it first clears existing servers (retrying up to 10 times to work around the resolver-replacement bug) before applying the new servers, returning `ReplaceDnsError` if servers cannot be cleared

### Requirement: SystemdResolvedDnsChangeWatch

The system SHALL allow watching for DNS configuration changes broadcast by systemd-resolved and SHALL expose async wrappers that run blocking D-Bus calls off the async runtime.

#### Scenario: Watching DNS server changes
- **GIVEN** a `SystemdResolved` handle with a registered match on `PropertiesChanged` for the `DNS` property at the resolve1 manager path
- **WHEN** systemd-resolved emits a DNS change and the `should_continue` predicate returns true
- **THEN** the provided callback is invoked with the deserialized `Vec<DnsServer>` and the D-Bus messages continue to be processed until `should_continue` returns false

#### Scenario: Async DNS operations
- **GIVEN** an `AsyncHandle` obtained from `async_handle()`
- **WHEN** `get_dns`, `set_dns`, `set_dns_state`, `disable_dot`, `set_domains`, or `revert_link` is awaited
- **THEN** the blocking D-Bus work runs inside `tokio::task::spawn_blocking`, surfacing `AsyncTaskError` if the spawned task fails to join

### Requirement: NetworkManagerWireguardTunnel

The system SHALL create and remove WireGuard tunnels via NetworkManager only when the detected NetworkManager version is new enough to support WireGuard.

#### Scenario: Creating a WireGuard tunnel
- **GIVEN** a `DeviceConfig` and a NetworkManager version at or above 1.16
- **WHEN** `create_wg_tunnel()` is called
- **THEN** it adds the connection (preferring `AddConnection2`, falling back to `AddConnectionUnsaved` on `UnknownMethod`), activates it, waits up to 15 seconds for the device to reach a ready state, and removes the tunnel if it does not become ready in time

#### Scenario: Rejecting an unsupported NetworkManager version
- **GIVEN** a NetworkManager whose version is below 1.16
- **WHEN** `nm_supports_wireguard()` is evaluated
- **THEN** it returns `NMTooOld(major, minor)`

### Requirement: NetworkManagerDnsManagement

The system SHALL set DNS servers on a NetworkManager-managed interface only when NetworkManager is detected, is managing `/etc/resolv.conf` (not via dnsmasq or in an unmanaged/none mode), and is old enough that its DNS handling works.

#### Scenario: Applying DNS to a managed device
- **GIVEN** a managed interface name and a list of DNS servers
- **WHEN** `set_dns()` is called
- **THEN** it fetches the device, waits until it is ready, preserves existing route configuration, sets the IPv4/IPv6 DNS settings with method `manual` and the highest DNS priority, and reapplies the connection settings, returning a backup of the prior settings

#### Scenario: Rejecting dnsmasq-managed DNS
- **GIVEN** NetworkManager whose DNS `Mode` property is `dnsmasq`
- **WHEN** `ensure_resolv_conf_is_managed()` is evaluated
- **THEN** it returns `UsingDnsmasq`

### Requirement: NetworkManagerConnectivityCheckToggle

The system SHALL be able to disable and re-enable NetworkManager's connectivity check, reporting the prior state, to avoid hangs when DNS is blocked by the firewall.

#### Scenario: Disabling the connectivity check
- **GIVEN** NetworkManager with `ConnectivityCheckEnabled` set to true
- **WHEN** `disable_connectivity_check()` is called
- **THEN** it sets the property to false and returns `Some(true)` to indicate the check was previously enabled and is now disabled

## Technical Notes

- **Implementation**: `src/lib.rs` (shared connection), `src/systemd.rs` (host state), `src/systemd_resolved.rs` (resolve1 DNS + async handle + change watch), `src/network_manager.rs` (NetworkManager tunnels/DNS/connectivity check).
- **Dependencies**: External `dbus` (blocking `SyncConnection`/`Proxy`), `libc` (`AF_INET`/`AF_INET6`), `tokio` (`spawn_blocking`), `thiserror`, `tracing`. The whole crate is gated behind `#![cfg(target_os = "linux")]`. Within the workspace it provides the low-level Linux D-Bus primitives consumed by higher-level DNS/route/firewall management used by the VPN tunnel state machine. Code is derived from Mullvad VPN's D-Bus integration.
