# nym-vpn-rpc-uniffi Specification

> Generated by openlore on 2026-06-26
> Source files: src/lib.rs, Cargo.toml

## Purpose

This crate generates UniFFI bindings for the daemon RPC client (`nym-vpn-proto::rpc_client::RpcClient`), exposing the desktop VPN daemon's control surface to foreign callers (notably the macOS app). It wraps the async RPC client as a single `RpcClient` UniFFI object, bridges a streaming event subscription into a foreign callback, and maps daemon and account errors into a foreign-visible `RpcError` type.

## Requirements

### Requirement: RpcClientSurface

The system MUST expose the daemon RPC client as a single async UniFFI `Object` whose methods clone the inner client and delegate to it, mapping daemon errors into the exported `RpcError`.

#### Scenario: Connecting to the daemon
- **GIVEN** a running VPN daemon reachable by the RPC client
- **WHEN** the foreign caller invokes the `RpcClient::new` async constructor
- **THEN** an inner `DaemonRpcClient` is created and a connection failure surfaces as `RpcError`

#### Scenario: Issuing a control or query call
- **GIVEN** a constructed `RpcClient`
- **WHEN** a method such as `connect_tunnel`, `get_tunnel_state`, `set_entry_point`, or `list_gateways` is awaited (on the Tokio async runtime)
- **THEN** the call is forwarded to the inner client and any `DaemonRpcError` is converted to `RpcError`

#### Scenario: macOS-only split-tunnel and diagnostics
- **GIVEN** the crate is compiled for `target_os = "macos"`
- **WHEN** the caller invokes split-tunnel methods (`add_split_tunnel_app`, `clear_split_tunnel_apps`, etc.), `need_full_disk_permissions`, or `run_diagnostic`
- **THEN** these additional methods are available and delegate to the inner client, whereas on other targets they are absent

### Requirement: EventStreamObserver

The system MUST allow a foreign `TunnelEventObserver` callback to subscribe to the daemon's tunnel event stream and MUST provide a cancellable handle that stops delivery on explicit cancel or on drop.

#### Scenario: Subscribing to tunnel events
- **GIVEN** a foreign object implementing `TunnelEventObserver`
- **WHEN** `RpcClient::listen_to_events(observer)` is awaited
- **THEN** a Tokio task forwards each `TunnelEvent` via `on_tunnel_event`, calls `on_close` when the stream ends or errors, and returns a `StreamObserver` handle

#### Scenario: Cancelling the subscription
- **GIVEN** an active `StreamObserver`
- **WHEN** `cancel()` is called or the `StreamObserver` is dropped
- **THEN** the underlying `CancellationToken` is cancelled and the forwarding task stops

### Requirement: RpcErrorMapping

The system MUST present a unified `RpcError` object that wraps either a daemon RPC error or an account-command error, exposes the underlying account error and a formatted error chain, and converts store/forget account responses carrying errors into `RpcError`.

#### Scenario: Account command error surfaced from store/forget
- **GIVEN** a `store_account` or `forget_account` response that contains an embedded error
- **WHEN** the method inspects the response
- **THEN** it returns `RpcError` wrapping the `AccountCommandError`, retrievable via `account_error()`

#### Scenario: Inspecting an error chain
- **GIVEN** an `RpcError` (either RPC or account variant)
- **WHEN** the caller calls `display_chain()` or the exported `Display`
- **THEN** the full underlying error chain is rendered as a string

## Technical Notes

- **Implementation**: `src/lib.rs` — `RpcClient` (`#[uniffi::export(async_runtime = "tokio")]`), `StreamObserver`, `TunnelEventObserver` (`with_foreign`), `RpcError`/`InnerRpcError`, plus a `#[cfg(target_os = "macos")]` impl block for split-tunnel and diagnostics.
- **Dependencies**: Wraps `nym-vpn-proto` (`rpc_client` feature) and shares types with `nym-vpn-lib-types` (`uniffi-bindings` + `serde`). Uses `uniffi` (`tokio` feature), `tokio`, `tokio-util` (`CancellationToken`), `futures`, and `nym-common` (`ErrorExt`). Built as `lib` + `staticlib`. In the workspace this crate is the desktop/daemon-facing FFI binding (the RPC client to a separately running daemon), complementing `nym-vpn-lib-uniffi` which embeds the VPN library directly for mobile.
