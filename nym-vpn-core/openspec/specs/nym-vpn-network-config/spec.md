## Purpose

Discovers and caches the Nym network environment configuration for a chosen network (mainnet, sandbox, canary, or any registered name). It bundles default discovery data, fetches up-to-date discovery, the set of registered networks, and full network details from the nym-vpn-api/nym-api, persists them to disk, and exposes a unified `Network` describing nyxd/nym-api/nym-vpn-api URLs, feature flags, account-management links, system messages, and scoring thresholds.

## Requirements

### Requirement: BundledDefaultDiscovery

The system SHALL provide pre-bundled default discovery and network details for mainnet (and sandbox/canary discovery), enabling a usable `Network` without any network access.

#### Scenario: ConstructMainnetWithoutNetwork
- **WHEN** `Network::mainnet_default` is called
- **THEN** a `Network` is constructed from the embedded mainnet discovery JSON and mainnet `NymNetworkDetails`, never failing unless the bundled data is invalid

#### Scenario: SelectDefaultDiscoveryByName
- **GIVEN** a network name of "mainnet", "sandbox", or "canary"
- **WHEN** `Discovery::default_discovery(name)` is called
- **THEN** the corresponding embedded discovery is returned, and any other name yields `None`

### Requirement: NetworkDiscoveryFetching

The system SHALL fetch registered networks, discovery for a named network, and network details from the API via a `Fetcher`, mapping each failure to a distinct error variant.

#### Scenario: FetchDiscoveryForNetwork
- **GIVEN** a `Fetcher` built from a discovery
- **WHEN** `fetch_discovery(network_name)` is called
- **THEN** the well-known discovery response is fetched and converted into a `Discovery`, or `Error::GetWellKnownDiscovery` / `Error::ConvertWellKnownDiscovery` on failure

#### Scenario: DropRetiredNetworks
- **WHEN** registered networks are fetched
- **THEN** retired network names (e.g. "evil") are removed from the resulting `RegisteredNetworks`

### Requirement: PersistentCacheWithStaleness

The system SHALL persist discovery, registered networks, and network details on disk with an update timestamp, treating records older than `MAX_FILE_AGE` (1 hour) or without a timestamp as stale, and re-fetch only stale records.

#### Scenario: RefreshOnlyStaleRecords
- **GIVEN** a `NetworkCache` with some up-to-date and some stale persistent records
- **WHEN** `fetch_if_stale` is called
- **THEN** only the stale records are re-fetched and updated, and fresh ones are left untouched

#### Scenario: LazyFetchNetworkDetailsForNonMainnet
- **GIVEN** a non-mainnet environment with no bundled network details
- **WHEN** `network()` is called before details are fetched
- **THEN** `Error::NetworkDetailsNotFetched` is returned, prompting a `fetch_if_stale` call to populate them

### Requirement: NetworkNameConsistency

The system SHALL reject construction of a `Network` when the discovery's network name does not match the network details' network name.

#### Scenario: MismatchedNetworkName
- **GIVEN** a discovery and network details with differing `network_name`
- **WHEN** `Network::new_from_discovery` is called
- **THEN** `Error::NetworkNameMismatch` is returned with the expected and actual names

### Requirement: NetworkDetailsPatching

The system SHALL patch missing or empty nym-vpn-api URLs in the network details using the discovery's nym-vpn-api URLs before building a `Network`.

#### Scenario: PatchMissingVpnApiUrls
- **GIVEN** network details whose `nym_vpn_api_urls` are absent or empty
- **WHEN** `NetworkCache::network` builds the network
- **THEN** the nym-vpn-api URLs are filled in from discovery

### Requirement: FeatureFlagAccess

The system SHALL expose feature flags parsed from discovery, supporting both flat values and grouped values, and provide typed accessors for known flags (stats recipient, gateway metadata-update version, domain fronting, QUIC, privy).

#### Scenario: ReadGroupedFlag
- **GIVEN** a discovery with a grouped feature flag such as `statistics.recipient`
- **WHEN** `Network::stats_recipient` (or another typed accessor) is queried
- **THEN** the value is parsed into its target type and returned, or `None` if absent or unparseable

### Requirement: PeriodicDiscoveryRefresh

The system SHALL run a `DiscoveryRefresher` background task that, while online and not paused, periodically (hourly) refreshes the network cache and emits an updated `Network` on change, and responds to pause/resume commands and a cancellation token.

#### Scenario: RefreshEmitsUpdatedNetwork
- **GIVEN** a running refresher that is online and unpaused
- **WHEN** the check interval elapses and `fetch_if_stale` updates the cache
- **THEN** a freshly built `Network` is sent over the events channel

#### Scenario: PauseSuppressesRefresh
- **GIVEN** a `DiscoveryRefresherCommand::Pause(true)` was received
- **WHEN** the interval ticks
- **THEN** no refresh is performed until resumed

## Technical Notes

- **Implementation**: `src/lib.rs` (`Network`, `NetworkCache`, `Error`, `PersistentRecord`), `src/discovery.rs`, `src/envs.rs` (`RegisteredNetworks`), `src/fetcher.rs`, `src/feature_flags.rs`, `src/nym_vpn_network.rs`, `src/discovery_refresher.rs`, `src/system_configuration.rs`, `src/account_management.rs`, and the `persistent_*` modules; bundled defaults live under `default/*.json`.

Within the workspace it is the configuration source of truth, supplying API URLs, feature flags, and score thresholds consumed by `nym-gateway-directory` and the higher-level VPN client crates.
