## Purpose

nym-windows provides low-level Windows-specific abstractions used by the VPN engine
on Windows. It wraps Win32 primitives for overlapped I/O, IP interface
configuration and change notifications, synchronization events, process/module
snapshots, hidden message-only windows (including power-management events), and
security descriptors / ACLs.

## Requirements

### Requirement: IpInterfaceConfiguration

The crate SHALL read, modify, and watch Windows IP interface entries.

#### Scenario: Observe IP interface changes
- **GIVEN** a registered change callback via `notify_ip_interface_change`
- **WHEN** an IP interface changes on the host
- **THEN** the callback is invoked, and entries can be read/updated via `get_ip_interface_entry`/`set_ip_interface_entry`

### Requirement: OverlappedIo

The crate SHALL provide a safe wrapper around Win32 OVERLAPPED structures for
asynchronous I/O.

#### Scenario: Issue overlapped I/O
- **GIVEN** an `Overlapped` created with an optional event
- **WHEN** it is passed to a Win32 async API
- **THEN** the operation can be awaited/completed via the associated event

### Requirement: SynchronizationEvents

The crate SHALL provide Win32 event objects for synchronization.

#### Scenario: Signal an event
- **GIVEN** an `Event` created with a reset mode
- **WHEN** `set()` is called
- **THEN** waiters on the event are released

### Requirement: ProcessAndModuleEnumeration

The crate SHALL enumerate running processes and their loaded modules via a
toolhelp snapshot.

#### Scenario: List processes
- **GIVEN** a `ProcessSnapshot`
- **WHEN** `processes()` / `modules()` are iterated
- **THEN** it yields `ProcessEntry` / `ModuleEntry` records for the snapshot

### Requirement: PowerManagementEvents

The crate SHALL listen for system power-management events through a hidden window.

#### Scenario: Detect suspend/resume
- **GIVEN** a `PowerManagementListener`
- **WHEN** the system emits a power event (e.g. suspend/resume)
- **THEN** a corresponding `PowerManagementEvent` is delivered

### Requirement: SecurityDescriptorsAndAcls

The crate SHALL construct and manipulate Windows security descriptors, ACLs, SIDs,
and trustees.

#### Scenario: Build an access-controlled object
- **GIVEN** the security module types (SIDs, ACLs, explicit access entries)
- **WHEN** a security descriptor is assembled
- **THEN** it can be applied to restrict access to a securable Windows object

## Technical Notes

- **Implementation**: `src/net.rs` (IP interface APIs), `src/io.rs` (`Overlapped`), `src/sync.rs` (`Event`), `src/process.rs` (`ProcessSnapshot`), `src/window.rs` (`create_hidden_window`, `PowerManagementListener`), `src/security/*` (descriptors/ACLs/SIDs)
- **Dependencies**: the `windows`/`windows-sys` crates (Win32 FFI); consumed by `nym-vpn-lib`, `nym-firewall`, `nym-routing`, `nym-dns`, and `nym-offline-monitor` on Windows
