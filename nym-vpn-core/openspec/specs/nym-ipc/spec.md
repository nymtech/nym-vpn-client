## Purpose

nym-ipc is the local inter-process transport that connects NymVPN clients (nym-vpnc, GUI) to the nym-vpnd daemon, providing tonic-compatible byte streams over a Unix domain socket (Linux, debug macOS), a Windows named pipe, or macOS XPC (release/`xpc`). It implements a small handshake protocol and per-platform client authentication (polkit prompt on Linux, code-signature verification on macOS/Windows, XPC built-in auth) so the daemon only serves connections from legitimate clients.

## Requirements

### Requirement: PlatformTransportSelection

The crate SHALL select the IPC transport at compile time based on target OS and build profile, exposing a uniform `client::connect` and (under feature `daemon`) `server::create_incoming` interface.

#### Scenario: LinuxAndDebugMacosUseUnixSocket
- **GIVEN** the target is Linux, or macOS in debug without the `xpc` feature
- **WHEN** `server::create_incoming` / `client::connect` is called
- **THEN** a Unix domain socket transport (`uds`) bound at the given socket path is used

#### Scenario: WindowsUsesNamedPipe
- **GIVEN** the target is Windows
- **WHEN** the transport is created
- **THEN** a named pipe (`named_pipe`) at the given pipe name is used

#### Scenario: ReleaseMacosUsesXpc
- **GIVEN** the target is macOS in release, or the `xpc` feature is enabled
- **WHEN** the transport is created
- **THEN** macOS XPC is used and `socket_path` is ignored

### Requirement: ConnectionHandshake

The client SHALL initiate every connection by sending an authentication query and reading the authentication result before treating the stream as usable, and SHALL map a denied/closed result to a connection error.

#### Scenario: AcceptedConnection
- **GIVEN** a client transport is opened
- **WHEN** `accepted` sends `AuthenticaticationQuery::Status` and receives `AuthenticaticationResult::Accepted`
- **THEN** the stream is wrapped in `TokioIo` and returned to the caller

#### Scenario: DeniedConnection
- **GIVEN** the daemon rejects the client
- **WHEN** the client receives `AuthenticaticationResult::Denied` (or `Closed`)
- **THEN** `connect` returns `PermissionDenied` (or `ConnectionRefused`)

### Requirement: ServerAuthenticationLayer

The daemon-side `AuthenticationLayer` SHALL, for each incoming connection, consume the client's query, run platform authentication, and yield the stream only when authorized (sending `Accepted`) otherwise dropping it (sending `Denied`).

#### Scenario: AuthorizeAndYield
- **GIVEN** an incoming stream with valid client credentials/signature
- **WHEN** `authorized_stream` calls `is_authenticated` and it returns `Ok`
- **THEN** `AuthenticaticationResult::Accepted` is sent and the stream is yielded to tonic

#### Scenario: DenyAndDrop
- **GIVEN** an incoming stream that fails authentication
- **WHEN** `is_authenticated` returns an error
- **THEN** `AuthenticaticationResult::Denied` is sent, a warning is logged, and the stream is not yielded

### Requirement: LinuxPolkitAuthorization

On Linux the daemon SHALL authorize a client by obtaining its peer credentials and running a polkit `CheckAuthorization` (registering the `com.nymvpn.vpnd.unix-access` action policy if not present), with a user-interaction timeout and cancellation on shutdown.

#### Scenario: PolkitPromptAuthorized
- **GIVEN** a client connects over the Unix socket on Linux
- **WHEN** the daemon reads peer `UnixCredentials` and polkit returns `is_authorized = true` within the 60s interaction window
- **THEN** the connection is authorized

#### Scenario: PolkitPolicyFallbackInstall
- **GIVEN** the polkit action is not yet registered and `/usr/share/polkit-1/actions` is not writable
- **WHEN** `install_polkit_policy` runs
- **THEN** it falls back to `/etc/polkit-1/actions` (creating the parent dir if needed), and errors only if no candidate directory is writable

### Requirement: SignatureBasedAuthorization

On macOS and Windows the daemon SHALL authorize clients by verifying code signatures (or rely on XPC's built-in authentication), and SHALL skip client verification when the daemon's own binary is unsigned or verification is explicitly disabled.

#### Scenario: WindowsCertificateVerification
- **GIVEN** the Windows daemon binary is signed with the expected Nym certificate serial number
- **WHEN** a client connects over the named pipe
- **THEN** `ProcessCertVerifier` verifies the client process certificate signature; verification failure yields `AuthorizationDenied`

#### Scenario: SkipWhenDaemonUnsigned
- **GIVEN** the daemon's own binary is not signed (e.g. test/dev build) or `disable_client_verification` is set
- **WHEN** `incoming` builds the authentication layer
- **THEN** authentication material is set to `None` and all clients are authorized without verification

### Requirement: SocketLifecycleAndPermissions

The Unix socket transport SHALL remove any stale socket file before binding, set the socket file mode to `0o666`, and remove the socket file on drop; the Windows named pipe SHALL restrict access via a security descriptor and reject remote clients.

#### Scenario: StaleSocketCleanup
- **GIVEN** a socket file already exists from a prior crashed run
- **WHEN** `uds::incoming` runs
- **THEN** the previous socket file is removed before `UnixListener::bind` and permissions are set to `0o666`

#### Scenario: NamedPipeSecurity
- **GIVEN** the daemon creates a named pipe listener on Windows
- **WHEN** `create_listener` builds the server
- **THEN** it applies a DACL granting World read/write, sets `reject_remote_clients(true)`, and only the first instance uses `first_pipe_instance`

### Requirement: HandshakeWireProtocol

The crate SHALL encode the handshake as single-byte enums (`AuthenticaticationQuery` and `AuthenticaticationResult`) with defined fallbacks for unknown or missing bytes.

#### Scenario: UnknownQueryByteIsUndefined
- **GIVEN** a received query byte other than `1`
- **WHEN** `AuthenticaticationQuery::from(u8)` is applied
- **THEN** it resolves to `Undefined` and `status()` is false

#### Scenario: MissingResultByteIsClosed
- **GIVEN** the stream is closed before a result byte is read
- **WHEN** `AuthenticaticationResult::recv` reads
- **THEN** it returns `Closed`

## Technical Notes

- **Implementation**: `src/client.rs` (`connect`, `accepted` handshake), `src/server.rs` (`create_incoming` transport dispatch), `src/uds.rs` (Unix socket listener + cleanup), `src/named_pipe.rs` (Windows named pipe listener + `Connector`), `src/auth_result.rs` (wire enums), `src/authentication/mod.rs` (`AuthenticationLayer`, `AuthenticationMaterial`, `authorized_stream`), `src/authentication/{linux,macos,windows}.rs` (per-platform `is_authenticated`/`incoming`/`skip_authentication_checks`), `src/xpc/` (macOS XPC transport).
- **Dependencies**: Built on `tonic` (`Connected` transport), `tokio`/`tokio-stream`/`tokio-util` for async I/O and cancellation, `hyper-util` (`TokioIo`) for the tonic-compatible wrapper. Linux daemon auth uses `nix` (peer credentials) and `zbus`/`zbus_polkit` (polkit). macOS uses `objc2`/`objc2-security` (SecCode signature checks) and XPC via `objc2-foundation`. Windows uses `nym-windows` (process cert verification, security descriptors) and the `windows` crate. The `daemon` feature gates all server-side code. Within the workspace, nym-ipc is the shared transport beneath `nym-vpn-proto`'s `RpcClient` (used by nym-vpnc and the GUI) and the daemon's command interface in nym-vpnd.
