## Purpose

`nym-vpn-proto` owns the gRPC/protobuf contract for the Nym VPN daemon (`NymVpnd` service). It compiles `proto/nym_vpn_service.proto` with tonic/prost into generated Rust types under `proto::`, provides bidirectional conversions between those wire types and the domain types in `nym-vpn-lib-types` (feature `conversions`), and ships an IPC-based async `RpcClient` for talking to the daemon over a Unix/named-pipe socket or serial transport (feature `rpc_client`).

## Requirements

### Requirement: ProtoCodeGeneration

The system SHALL generate Rust types for the `nym_vpn_service` protobuf package from `proto/nym_vpn_service.proto` at build time and expose them under the `proto` module, re-exporting `prost_types::Timestamp` for timestamp interop.

#### Scenario: BuildCompilesProto
- **GIVEN** the crate is built
- **WHEN** `build.rs` runs `tonic_prost_build::compile_protos("proto/nym_vpn_service.proto")`
- **THEN** the generated service, client, and message types are included via `tonic::include_proto!("nym_vpn_service")` into `proto`

### Requirement: DaemonServiceSurface

The system SHALL define the `NymVpnd` gRPC service exposing the daemon's full control surface — info/config queries, granular `Set*` configuration setters, tunnel lifecycle calls (`ConnectTunnel`, `ReconnectTunnel`, `DisconnectTunnel`, `GetTunnelState`), gateway listing, account/device/ticketbook management, diagnostics, sentry, network statistics, socks5, deeplinks, and split-tunnel operations.

#### Scenario: EventStreamingRpc
- **GIVEN** a connected client
- **WHEN** it calls `ListenToEvents(google.protobuf.Empty)`
- **THEN** the service returns a server-side `stream TunnelEvent` of tunnel/mixnet/config/account events

#### Scenario: TunnelLifecycleRpcs
- **GIVEN** the `NymVpnd` service definition
- **WHEN** the contract is inspected
- **THEN** it includes `ConnectTunnel`, `ReconnectTunnel`, and `DisconnectTunnel` each returning `google.protobuf.BoolValue`, and `GetTunnelState` returning a `TunnelState` message

### Requirement: BidirectionalDomainConversions

The system SHALL, under the `conversions` feature, provide `From`/`TryFrom` implementations converting between generated `proto::*` wire types and `nym-vpn-lib-types` domain types in both directions (e.g. `TunnelState`, `TunnelEvent`, `Gateway`, `VpnServiceConfig`, `UserAgent`, account state).

#### Scenario: WireToDomainTunnelState
- **GIVEN** a `proto::TunnelState` received from the daemon
- **WHEN** `TunnelState::try_from` is invoked
- **THEN** it yields the domain `nym_vpn_lib_types::TunnelState`, or a `ConversionError` if a required field is unset or an enum value fails to decode

#### Scenario: RoundTripUserAgent
- **GIVEN** a `nym_vpn_lib_types::UserAgent`
- **WHEN** it is converted to `proto::UserAgent` and back
- **THEN** the application, version, platform, and git_commit fields are preserved

### Requirement: ConversionErrorReporting

The system SHALL surface conversion failures through a single `ConversionError` type distinguishing unset values (`NoValueSet`), enum decode failures (`Decode`), time/address/integer parse failures, UTF-8 encoding failures, and user-agent parse failures, each annotated with the offending field name.

#### Scenario: MissingRequiredFieldRejected
- **GIVEN** a proto message missing a required oneof/field (e.g. `TunnelState.state`)
- **WHEN** the corresponding `TryFrom` conversion runs
- **THEN** it returns `ConversionError::NoValueSet("TunnelState.state")`

### Requirement: TimestampConversion

The system SHALL convert between `prost_types::Timestamp` and `time::OffsetDateTime`, combining seconds and nanoseconds, and report range errors as `time::Error`.

#### Scenario: ProtoTimestampToOffsetDateTime
- **GIVEN** a `prost_types::Timestamp`
- **WHEN** `prost_timestamp_into_offset_datetime` is called
- **THEN** it returns an `OffsetDateTime` from the unix seconds plus nanoseconds, or `Err(time::Error)` if out of range

### Requirement: DaemonRpcClient

The system SHALL, under the `rpc_client` feature, provide an async `RpcClient` that connects to the daemon over its IPC socket (or a serial connector), exposes typed async methods returning `nym-vpn-lib-types` domain types, and maps transport, RPC, request-serialization, response-parsing, and permission failures to a dedicated `Error` enum.

#### Scenario: PermissionDeniedBecomesAuthRequired
- **GIVEN** the daemon socket connection fails with `PermissionDenied`
- **WHEN** `RpcClient::new()` resolves the error chain
- **THEN** it returns `Error::AuthenticationRequired` instead of a raw transport error

#### Scenario: ResponseParsedIntoDomainType
- **GIVEN** a successful RPC response (e.g. from `GetTunnelState`)
- **WHEN** the client method runs
- **THEN** the proto response is converted via `TryFrom` to its domain type, with conversion failures returned as `Error::InvalidResponse(ConversionError)`

## Technical Notes

- **Implementation**: `crates/nym-vpn-proto/proto/nym_vpn_service.proto` (84 messages, `NymVpnd` service with 83 rpc methods), `build.rs`, `src/lib.rs` (`proto` module + feature-gated `conversions`/`rpc_client`), `src/conversions/` (per-domain `From`/`TryFrom` impls + `ConversionError` + `prost` timestamp helpers), `src/rpc_client.rs` (`RpcClient`, `Error`, `get_rpc_socket_path`).
- **Dependencies**: `tonic`/`tonic-prost`/`prost`/`prost-types` for gRPC codegen; `nym-vpn-lib-types` (with `serde`) as the domain-type target for conversions; `nym-ipc` for socket transport, `tokio-stream`/`tower`/`hyper` for the client; `thiserror`/`time`/`serde_json` for conversions. Default build emits only generated proto types; `conversions` and `rpc_client` are opt-in. This crate is the wire/contract boundary between daemon and clients — it depends on `nym-vpn-lib-types` for the canonical domain model and translates it to/from protobuf.
