## Purpose

Discovers, filters, scores, and selects Nym mixnet/WireGuard gateways for use as VPN entry and exit nodes. It fetches gateway directories from the `nym-vpn-api` and `nym-api`, models them as a filterable `GatewayList`, resolves user-specified entry/exit points (by identity, country, region, or random) to concrete gateways, and exposes a background cache that keeps gateway data fresh.

## Requirements

### Requirement: GatewayClientConstruction

The system SHALL construct a `GatewayClient` from a `Config` that MUST contain at least one nym-api URL and at least one nym-vpn-api URL, rejecting empty URL lists with `Error::InvalidConfiguration`.

#### Scenario: RejectEmptyApiUrls
- **GIVEN** a `Config::new` call with an empty `nym_api_urls` or `nym_vpn_api_urls` vector
- **WHEN** the configuration is validated
- **THEN** construction returns `Error::InvalidConfiguration`

#### Scenario: BuildClientsFromConfig
- **GIVEN** a valid `Config` and a `UserAgent`
- **WHEN** `GatewayClient::new` is called
- **THEN** a fronted HTTP nym-api client and a `VpnApiClient` are created using the configured URLs

### Requirement: GatewayDirectoryLookup

The system SHALL fetch gateways from the nym-vpn-api by `GatewayType` (MixnetEntry, MixnetExit, Wg) and from the nym-api as described/skimmed nodes, parsing each into a `Gateway` and skipping entries that fail to parse.

#### Scenario: LookupTypedGatewaysFromVpnApi
- **WHEN** `lookup_gateways(gw_type)` is called
- **THEN** the client requests gateways of that type from the vpn-api, parses them, drops mixnet-blacklisted gateways via `not_mixnet_blacklisted`, and returns a typed `GatewayList`

#### Scenario: ResolveGatewayIp
- **GIVEN** a gateway identity string
- **WHEN** `lookup_gateway_ip` is called
- **THEN** the matching gateway's first IP is returned, or `Error::RequestedGatewayIdNotFound` / `Error::FailedToLookupIp` if no IP can be resolved

### Requirement: PerformanceFiltering

The system SHALL apply a configured minimum mixnet performance threshold, retaining only gateways whose `mixnet_performance` meets or exceeds the threshold.

#### Scenario: FilterBelowMinimumPerformance
- **GIVEN** a `GatewayClient` configured with a `mixnet_min_performance`
- **WHEN** gateways are fetched from the nym-api
- **THEN** gateways with a mixnet performance below the threshold are removed from the returned list

### Requirement: EntryAndExitGatewaySelection

The system SHALL resolve an `EntryPoint` or `ExitPoint` (Gateway identity, Country, Region, Random, or exit Address) to a concrete `Gateway`, applying the supplied filters and returning a location-specific or random-selection error when no gateway matches.

#### Scenario: SelectByCountry
- **GIVEN** an `EntryPoint::Country` with a two-letter ISO code and a populated `GatewayList`
- **WHEN** `find_entry_gateway` is called
- **THEN** a random gateway in that country matching the filters is returned, or `Error::NoMatchingEntryGatewayForLocation` listing available countries

#### Scenario: SelectByExplicitIdentity
- **GIVEN** an `ExitPoint::Gateway` identity not present in the list
- **WHEN** `find_exit_gateway` is called
- **THEN** `Error::NoMatchingGateway` is returned with the requested identity

### Requirement: DescendingScoreSelection

The system SHALL select the "best" gateway by trying minimum score values in descending order (High, then Medium, then Low) and returning the first matching gateway, continuing to a lower score only when the failure is a non-specific unmatched-gateway error.

#### Scenario: FallBackToLowerScore
- **GIVEN** no gateway meets the High score filter but one meets Medium
- **WHEN** `find_best_entry_point_gateway` (or `find_best_exit_point_gateway` / `find_best_socks5_gateway`) is called
- **THEN** selection retries at Medium and returns the matching gateway

### Requirement: GatewayCaching

The system SHALL run an async `GatewayCache` actor that fetches gateway lists on demand, serves cached results younger than `MAX_CACHE_AGE` (5 minutes), refreshes only stale types, falls back to stale/cached data when offline, and invalidates the cache on environment change or gateway-client replacement.

#### Scenario: ServeFreshCacheWithoutRefetch
- **GIVEN** a cached gateway list younger than `MAX_CACHE_AGE`
- **WHEN** `lookup_gateways` is requested through `GatewayCacheHandle`
- **THEN** the cached list is returned without contacting the API

#### Scenario: RefuseRefreshWhenOffline
- **GIVEN** the connectivity handle reports offline and the cache is empty
- **WHEN** a refresh is attempted
- **THEN** the operation does not fetch and returns `Error::Offline` (or stale cached data if present)

### Requirement: GatewayBlacklisting

The system SHALL maintain a thread-safe, TTL-bounded `BlacklistedGateways` set (20-minute TTL) used as a `NotBlacklisted` filter, where expired entries are automatically purged on add/remove and lookups treat expired entries as absent.

#### Scenario: BlacklistedGatewayExpires
- **GIVEN** a gateway identity added to the blacklist
- **WHEN** its TTL has elapsed and `exists` is queried
- **THEN** the gateway is reported as not blacklisted

## Technical Notes

- **Implementation**: `src/gateway_client.rs` (fetching), `src/entries/gateway/mod.rs` (`Gateway`, `GatewayList`, `GatewayFilter(s)`, scoring/selection), `src/gateway_cache.rs` (background cache actor), `src/blacklisted_gateways.rs`, `src/entries/{entry_point,exit_point,country,ipr_addresses}.rs`.
- **Dependencies**: `nym-vpn-api-client` (typed gateway directory + probe/score data), `nym-validator-client`/`nym-api` (described & skimmed nodes), `nym-sdk` (`NodeIdentity`, `Recipient`, `UserAgent`), `nym-topology`, `nym-offline-monitor` (connectivity gating for the cache), `nym-network-defaults` (`ApiUrl`). Within the workspace this crate is the gateway-selection layer consumed by the tunnel/VPN orchestration crates to choose entry/exit nodes; it pairs with `nym-vpn-network-config` which supplies the API URLs and feature flags it is configured with.
